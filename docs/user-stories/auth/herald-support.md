# Herald 鉴权支持 用户故事

> 角色：**空间参与者**与**部署者**，定义见 [`docs/user-stories/_roles.md`](../_roles.md)。
> 关联：[正式 PRD](../../prd/auth/herald-support.md)、[正式 PRD data-sync](../../prd/core/data-sync.md)。
> 术语：登录 = 在启用鉴权的服务器上经 Herald 授权窗口完成认证并持有访问凭证；门禁 = 服务端对业务访问的前置用户身份校验，与空间密钥（空间寻址）正交。

## 用户故事

### 故事 1：在启用鉴权的服务器上登录后使用同步 [US-HS-001]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者
**我希望**：当我连接的服务器启用了 Herald 鉴权时，在同步区完成一次登录，之后照常使用全部同步功能
**从而**：受保护服务器上的团队脚本只对完成登录的成员可用，而我的日常同步操作与无鉴权服务器一样顺手

**【验收标准】**

**场景 1：登录后照常协作**
```gherkin
Given 我连接的服务器启用了 Herald 鉴权，同步区呈现"需要登录"引导
When 我点击登录，在弹出的授权窗口完成 Herald 账号认证（账号有效，即使没有同步权限点或角色）
Then 授权窗口自动关闭，同步区显示我已登录；此后创建/加入空间、保存脚本、拉取与切换版本等全部同步操作的行为与无鉴权服务器一致（门禁不改变空间协作语义）
```

**场景 2：登录状态自动延续**
```gherkin
Given 我此前已登录，某次同步操作时访问凭证已过期
When 我继续执行该同步操作
Then 系统自动完成凭证续期并继续本次操作，全程无需我重新登录或干预
```

**场景 3：续期失败引导重新登录（失败场景）**
```gherkin
Given 我的登录凭证已彻底失效（如长期未使用，或账号在 Herald 侧被停用）
When 我执行同步操作
Then 操作被拒绝并明确提示需要重新登录，引导我重走登录流程；我的本机流程、空间清单与已拉取内容不受影响
```

### 故事 2：登录状态管理 [US-HS-002]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者
**我希望**：随时可以登出；更换服务器地址时自动清掉旧服务器的登录状态；连接无鉴权服务器时不看到任何登录界面
**从而**：登录状态只属于当前服务器，不串扰、不残留；不启用鉴权的团队完全无感

**【验收标准】**

**场景 1：登出**
```gherkin
Given 我已登录某启用鉴权的服务器
When 我在同步区点击登出并确认
Then 本机清除该服务器的登录状态，后续同步操作重新要求登录；登出前尚未完成的登录或续期即使随后成功也不恢复登录态；我的空间清单、本机流程与已拉取内容不受影响
```

**场景 2：切换服务器清登录态**
```gherkin
Given 我已登录服务器 A，现把扩展的服务器地址改为 B
When 服务器地址切换生效
Then 服务器 A 的登录状态随既有"换服务器清空同步关联"一并清除，旧请求即使在切回 A 后返回也不能恢复旧登录态；扩展按服务器 B 自身的模式重新呈现（要求登录则引导登录，不要求则无登录界面）
```

**场景 3：无鉴权服务器零感知**
```gherkin
Given 我连接的服务器显式配置为无鉴权模式
When 我使用全部同步功能
Then 不出现任何登录入口、登录提示或登录状态展示，行为与升级前完全一致
```

### 故事 3：部署双运行模式 [US-HS-003]

**优先级**: P0

**【用户故事】**
**作为**：部署者
**我希望**：默认部署即带 Herald 鉴权（缺配置时启动即失败并给出完整配置指引），显式选择无鉴权模式才保留原行为
**从而**：对外开放的服务端天然有访问门禁，不会因"忘了配置"而裸奔；内网与本地开发场景仍可显式选择无鉴权

**【验收标准】**

**场景 1：默认鉴权缺配置启动失败（fail-fast）**
```gherkin
Given 我部署新版服务端，未做任何鉴权相关配置
When 服务端启动
Then 启动失败，错误信息指明缺少的 Herald 连接配置项，并给出两条出路：补齐鉴权配置，或显式选择无鉴权模式
```

**场景 2：显式无鉴权模式保持现状**
```gherkin
Given 我按发布说明显式配置无鉴权模式
When 服务端启动并承载同步业务
Then 行为与升级前版本一致：业务访问仍仅凭空间密钥，无任何登录要求
```

**场景 3：升级迁移有指引**
```gherkin
Given 我在既有部署上升级到默认带鉴权的版本
When 我阅读发布说明与启动报错信息
Then 我能明确知道需要做什么（配置 Herald 参数启用鉴权，或显式声明无鉴权），不存在第三种隐式状态
```

### 故事 4：鉴权门禁异常可见 [US-HS-004]

**优先级**: P1

**【用户故事】**
**作为**：空间参与者
**我希望**：当服务端的鉴权依赖（Herald）不可用时，同步操作给出明确失败原因并可重试，本地流程完全不受影响
**从而**：我知道问题出在服务端门禁而不是我的操作，本地工作不中断，恢复后无需重新配置即可继续

**【验收标准】**

**场景 1：门禁不可用时拒绝且不含糊**
```gherkin
Given 服务器启用了 Herald 鉴权，Herald 服务暂时不可用
When 我执行同步操作（保存脚本、拉取版本等）
Then 操作失败并明确提示服务端鉴权暂不可用、可稍后重试；未认证的访问不会被静默放行；我的本机流程照常执行，进行中的运行不被中断或重启
```

**场景 2：账号停用在下一次校验时生效**
```gherkin
Given 我已成功执行同步操作，随后管理员在 Herald 侧完成了我的账号停用
When 我再次执行同步操作
Then 登录校验拒绝访问并引导重新登录；权限或角色变化不影响有效登录账号的同步访问；本机流程、空间清单与已拉取内容保留不受影响
```
