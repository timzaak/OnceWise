# 空间权限与角色（space-permissions）用户故事

> 角色：**空间参与者**与**部署者**，定义见 [`docs/user-stories/_roles.md`](../_roles.md)；本 feature 内空间参与者按能力分级为**所有者 / 管理员 / 只读成员**（分级已并入该文件；映射 Herald 组织档位 org-owner / org-admin / org-member），成员与角色事实托管于 Herald 组织层。
> 关联：[正式 PRD](../../prd/auth/space-permissions.md)、[正式 PRD data-sync](../../prd/core/data-sync.md)、[正式 PRD herald-support](../../prd/auth/herald-support.md)。
> 术语：**组织绑定空间** = Herald 鉴权模式下新建、受角色权限保护的空间（无空间码）；**存量密钥空间** = 升级前已存在、保持密钥对等的空间；**邀请码** = 管理员签发的单次加入凭证。

## 用户故事

### 故事 1：创建受保护空间并成为所有者 [US-WP-001]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者（创建者）
**我希望**：在启用 Herald 鉴权的服务器上创建的空间自动受组织权限保护，我成为其所有者
**从而**：空间内容只对我邀请的成员开放，我随时可以收回任何人的访问权

**【验收标准】**

**场景 1：创建即保护**
```gherkin
Given 我已登录启用 Herald 鉴权的服务器
When 我在同步区创建空间（输入空间名称）
Then 空间创建成功并记入本机清单，显示我的角色为「所有者」；该空间不提供空间码，加入只能凭我签发的邀请码
```

**场景 2：权限服务不可用时创建失败（失败场景）**
```gherkin
Given 我已登录，但服务端的权限依赖（Herald）暂时不可用
When 我创建空间
Then 创建失败并明确提示服务端权限服务暂不可用、可稍后重试；不产生"空间已建但不受保护"或"已建但创建者不在成员中"的半成品空间，本机也不记录该空间
```

### 故事 2：签发一次性邀请码 [US-WP-002]

**优先级**: P0

**【用户故事】**
**作为**：空间管理员（或所有者）
**我希望**：为空间签发一次性邀请码，经现有渠道发给同事，粘贴即可加入
**从而**：不用逐个登记账号就能扩大协作范围，且每个码只能用一次，转发泄露的影响被限制在单人单次

**【验收标准】**

**场景 1：签发与分享**
```gherkin
Given 我是某组织绑定空间的管理员
When 我在成员界面签发邀请码
Then 界面展示新生成的邀请码并明示其单次有效与有效期规则，提供复制操作且有复制成功反馈；同一空间可同时存在多枚有效邀请码
```

**场景 2：已使用的码不能再用（失败场景）**
```gherkin
Given 某邀请码已被一位同事成功使用
When 另一人再使用同一邀请码加入
Then 加入被拒绝并明确提示邀请码已被使用；使用者的本机不记录该空间
```

**场景 3：过期码不能使用（失败场景）**
```gherkin
Given 某邀请码已超过其有效期
When 使用者使用该码加入
Then 加入被拒绝并明确提示邀请码已过期；使用者的本机不记录该空间
```

### 故事 3：凭邀请码加入空间 [US-WP-003]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者（加入者）
**我希望**：粘贴管理员分享的邀请码即加入空间，自动成为只读成员
**从而**：无需注册审批就能使用团队脚本，同时明确的角色让我知道自己在空间里能做什么

**【验收标准】**

**场景 1：凭码加入为只读成员**
```gherkin
Given 我已登录同一服务器，并收到管理员分享的有效邀请码
When 我在同步区粘贴邀请码并加入
Then 服务端核销该码并把我登记为该空间的只读成员；空间记入本机清单并显示我的角色「成员（只读）」
```

**场景 2：格式不合法的码本地拒绝（失败场景）**
```gherkin
Given 我粘贴的邀请码格式不合法
When 我提交加入
Then 本机直接拒绝并提示原因，不发起网络请求
```

**场景 3：未登录时先登录、码不被浪费（失败场景）**
```gherkin
Given 我尚未在该服务器登录
When 我使用一枚有效邀请码加入
Then 提示需要登录并引导我完成登录；登录后用同一枚邀请码可成功加入（该码在此期间未被消费）
```

### 故事 4：只读成员使用同步 [US-WP-004]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者（只读成员）
**我希望**：照常浏览脚本与版本、拉取选定版本到本机使用；尝试写入时得到明确的只读提示
**从而**：团队统一分发脚本、个人本机使用不受打扰，也不会误改共享内容

**【验收标准】**

**场景 1：浏览与拉取照常**
```gherkin
Given 我是某组织绑定空间的只读成员
When 我浏览脚本列表、版本列表与内容摘要，并拉取选定版本
Then 全部行为与既有空间参与者的读语义一致：同一全量校验、进入本机默认未启用、本地固定所选版本、新版本仅提示
```

**场景 2：写与管理操作被拒（失败场景）**
```gherkin
Given 我是某组织绑定空间的只读成员
When 我尝试把本机流程保存为该空间的脚本、发布新版本、修改脚本名称或备注，或删除该空间、打开成员管理
Then 操作被拒绝并明确提示该操作需要管理员权限（我当前是只读成员）；我的本机流程与已拉取内容不受任何影响
```

### 故事 5：管理员读写与成员管理 [US-WP-005]

**优先级**: P0

**【用户故事】**
**作为**：空间管理员（或所有者）
**我希望**：拥有全部读写能力，并能在成员界面查看成员、调整角色、移除成员；成员也可以自行退出
**从而**：空间里的脚本由少数人维护、多数人使用，人员变动时访问权即时收回

**【验收标准】**

**场景 1：管理员读写照常**
```gherkin
Given 我是某组织绑定空间的管理员
When 我保存脚本、发布新版本、修改名称或备注
Then 全部行为与既有空间参与者的写语义一致；只读成员能看到新版本提示并照常拉取
```

**场景 2：查看成员与调整角色**
```gherkin
Given 我是某组织绑定空间的管理员
When 我打开成员界面并把某只读成员提升为管理员
Then 成员列表展示各成员的身份标识与角色（所有者有专门标记）；被提升者的下一次写操作即可成功；反之把管理员降为只读成员后，其下一次写操作被拒并提示只读
```

**场景 3：移除成员即时生效**
```gherkin
Given 我是某组织绑定空间的管理员，成员列表中有一位只读成员
When 我移除该成员
Then 移除近即时生效：该成员下一次对该空间的任何同步操作被拒并明确提示已无访问权；其本机数据与已拉取内容保留（本地优先），其持有的任何旧邀请码不能使其重新加入
```

**场景 4：最后管理员保护（失败场景）**
```gherkin
Given 某组织绑定空间内管理员档（含所有者）只剩一名成员
When 有操作会使空间失去全部管理员档成员（移除或降级该成员）
Then 操作被拒绝并提示先转移管理权（提升他人或转移所有权）；空间不处于无管理者状态
```

**场景 5：成员自主退出**
```gherkin
Given 我是某组织绑定空间的只读成员（或管理员，且我不是所有者、也不是最后一名管理员档成员）
When 我确认退出该空间
Then 我的服务端成员关系被移除，后续访问提示无权限；我的本机流程与已拉取内容保留，本机清单条目由我另行"忘记"
```

### 故事 6：所有权转移 [US-WP-006]

**优先级**: P1

**【用户故事】**
**作为**：空间所有者
**我希望**：把所有权一步转移给某位管理员
**从而**：人员变动或交接时空间的最终控制权明确转移，且转移过程不会让空间处于无人负责的中间状态

**【验收标准】**

**场景 1：原子转移**
```gherkin
Given 我是某组织绑定空间的所有者，空间中有一位管理员
When 我把所有权转移给该管理员并确认
Then 转移一步完成：对方成为所有者，我降为管理员；成员列表即时反映新身份；原所有者与新所有者的其余权限不变
```

**场景 2：非所有者不能转移（失败场景）**
```gherkin
Given 我是某组织绑定空间的管理员（非所有者）
When 我尝试转移所有权
Then 操作被拒绝并明确提示仅所有者可转移所有权
```

### 故事 7：存量空间与无鉴权部署零变化 [US-WP-007]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者
**我希望**：服务器升级后，升级前已有的密钥空间以及无鉴权部署的行为与升级前完全一致
**从而**：既有协作不被升级打断，不需要任何迁移动作

**【验收标准】**

**场景 1：存量密钥空间照常**
```gherkin
Given 服务器启用 Herald 鉴权并升级到本功能版本，升级前已存在若干密钥空间
When 任何持码参与者对这些空间执行全部同步操作（凭空间码加入、对等读写、忘记、删除）
Then 行为与升级前完全一致；这些空间不出现成员、角色或邀请码界面，也不会被绑定组织
```

**场景 2：无鉴权部署零变化**
```gherkin
Given 我连接的服务器显式配置为无鉴权模式
When 我使用全部同步功能并创建新空间
Then 不出现任何权限、成员或邀请码界面与要求；新建空间仍为密钥对等空间，行为与升级前完全一致
```

### 故事 8：部署组织接入配置 [US-WP-008]

**优先级**: P0

**【用户故事】**
**作为**：部署者
**我希望**：Herald 鉴权模式默认要求完成组织接入配置（缺配置启动失败并给出可照做的指引），升级路径在发布说明中完整
**从而**：对外开放的服务端升级后即具备空间权限能力，不会因漏配而以无权限形态运行

**【验收标准】**

**场景 1：缺配置启动失败且有指引（fail-fast）**
```gherkin
Given 我部署新版服务端并选择 Herald 鉴权模式，但未配置组织接入凭证
When 服务端启动
Then 启动失败，错误信息指明所缺配置项，并列出 Herald 控制台需完成的准备动作（创建客户端应用、签发绑定该应用的 API key、授予组织管理策略）；仅凭报错即可完成配置，无需查阅源码
```

**场景 2：升级迁移有指引**
```gherkin
Given 我在既有 Herald 鉴权部署上升级到本版本
When 我阅读发布说明与启动报错
Then 我能明确知道补齐组织接入配置即可启动，存量空间不受任何影响，不存在第三种隐式状态
```

### 故事 9：权限依赖异常可见 [US-WP-009]

**优先级**: P1

**【用户故事】**
**作为**：空间参与者
**我希望**：权限判定所依赖的服务不可用时，同步操作给出明确失败原因并可重试，本地流程完全不受影响
**从而**：我知道问题出在服务端权限依赖而不是我的操作，本地工作不中断，恢复后无需重新配置即可继续

**【验收标准】**

**场景 1：权限服务不可用时拒绝且不含糊**
```gherkin
Given 服务器启用 Herald 鉴权与空间权限，Herald 服务暂时不可用
When 我执行受权限保护的同步操作（创建空间、签发或使用邀请码、成员管理、读写脚本）
Then 操作失败并明确提示服务端权限服务暂不可用、可稍后重试；不会放行任何未完成权限判定的访问；我的本机流程照常执行，进行中的运行不被中断或重启
```

**场景 2：结果不确定时先核对再重试**
```gherkin
Given 我执行一项成员管理或加入操作，请求超时且结果未知
When 我查看同步区反馈
Then 界面提示操作结果不确定并引导我先刷新成员列表核对结果，再决定是否重试；不会出现同一邀请码被重复核销或成员状态自相矛盾的可见结果
```
