# 用户故事角色定义

> 本文件是用户故事的统一角色参考。用户故事中的角色必须引用此处定义，不得在故事内重复定义；新增或修改角色时先更新本文件，再在用户故事中引用。

## AI 工具用户

- **定义**：已在日常使用 Codex、Claude Code 等 AI 编程工具，能在自有工具协助下描述、探索并验证网页局部操作，希望把验证过的操作固化为可开关流程重复使用的人。
- **特征**：不写站点专用脚本，不依赖开发者维护插件；熟悉自有 AI 工具的 Skill 与 MCP 配置；对启用流程后的自动执行结果（含保存/提交/确认类动作）自行承担风险边界。
- **诉求**：不依赖开发者，把一次验证成功的网页操作固化为可开关流程并可靠复用，在流程出错时能自己定位与维护。

## 空间参与者（创建者 / 加入者）

- **定义**：使用同步空间的 AI 工具用户，按空间类别分两种进入方式：**密钥空间**——"创建者"在本机生成空间 ID 与密钥并注册到自建服务器，"加入者"凭创建者分享的空间码（`空间ID#密钥`）加入，持码者权限完全对等；**组织绑定空间**（Herald 鉴权模式下新建，见 [`auth/space-permissions.md`](auth/space-permissions.md)）——创建者成为**所有者**，其他人凭管理员签发的一次性邀请码加入为**只读成员**，经管理者提升后成为**管理员**。
- **特征**：密钥空间服务端无账号体系，"持有密钥"即全部访问依据；组织绑定空间的成员资格与角色托管于 Herald 组织层，移除/降级在下一次访问即生效。空间清单只保存在各端本机；本机可能已有启用中的流程，自主决定本机使用哪个脚本版本，本地执行版本不被他人更新自动改变。
- **诉求**：免注册地把团队验证过的脚本共享起来，直接使用，不被他人更新打扰，出问题时能回退；空间不再使用时可本机忘记或服务端删除（组织绑定空间的服务端删除为管理员能力）。
- **边界**：不代替他人启用流程；密钥空间"分享对象即协作范围"（互信小圈子定位），组织绑定空间按"成员资格 + 角色"授权并可按人收回——只读成员不写共享内容，所有者不可被移除或降级。

## 部署者

- **定义**：自建 oncewise-ai-sync 同步服务端的团队运维者，负责 Herald 连接配置（实例地址、realm、客户端标识、回调地址注册）、组织接入凭证（绑定客户端应用的 API key 与组织管理策略授予）与运行模式选择。
- **特征**：默认部署即要求 Herald 鉴权（缺配置时启动失败并获得补齐配置或显式无鉴权的两条出路）；对外开放部署的空间权限（组织绑定空间）依赖组织接入凭证，缺配置同样启动失败并获得 Herald 控制台准备指引；内网与本地开发可显式选择无鉴权模式；Herald 侧的 realm/client 注册、API key 与账号管理属部署侧控制台动作。
- **诉求**：对外开放的自建服务端天然带访问门禁与空间权限能力，不因漏配而裸奔；升级与迁移路径在发布说明中完整可循。
- **边界**：不介入空间协作与脚本内容；服务端不保存其所辖用户与空间的关联，无自建成员、角色或审计概念（组织绑定空间的成员与角色事实托管于 Herald 组织层，服务端仅存空间-组织关联）。
