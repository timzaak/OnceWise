# 脚本同步与空间协作 用户故事

> 角色：**空间参与者**（创建者 / 加入者，同一角色的两种进入方式），定义见 [`docs/user-stories/_roles.md`](../_roles.md)。
> 关联：[正式 PRD](../../prd/core/data-sync.md)、[self-service-browser-automation 用户故事](self-service-browser-automation.md)。
> 术语：脚本 = 自动化流程（受约束步骤树定义）进入同步空间后的称呼，数据格式与安全语义与流程一致；空间码 = `空间ID#密钥`，本机生成、经现有渠道分享。

## 用户故事

### 故事 1：配置同步服务并创建空间 [US-DS-001]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者（创建者）
**我希望**：在扩展同步区配置团队自建服务器地址，然后一键创建一个空间作为团队的脚本共享地——空间 ID 与密钥都自动在本机生成
**从而**：不需要注册任何账号，团队就有了统一的脚本存放地，我把空间码发给同事即可开始协作

**【验收标准】**

**场景 1：配置服务器并创建空间**
```gherkin
Given 我首次使用同步能力，侧边栏同步区呈现服务器配置引导
When 我填写服务器地址并连接（浏览器原生确认扩展访问该地址），输入空间名称点击创建
Then 空间 ID 与密钥在本机生成、服务端注册成功后出现在我的空间清单中并被选中；空间码可查看、可复制；我的本地流程功能不受任何影响
```

**场景 2：不配置不影响本地（local-first）**
```gherkin
Given 我未配置服务器或不打算使用同步
When 我继续使用扩展的流程导入、启用与执行功能
Then 全部本地功能照常可用，同步区仅呈现配置引导（DEC-data-sync-005 / DEC-data-sync-008）
```

### 故事 2：凭空间码加入空间 [US-DS-002]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者（加入者）
**我希望**：把同事发来的空间码粘贴进同步区即加入该空间
**从而**：无需注册登录、无需管理员审批，即刻看到空间内全部脚本

**【验收标准】**

**场景 1：凭码加入**
```gherkin
Given 同事把空间码发给我（IM 等现有渠道）
When 我在同步区粘贴空间码并点击加入
Then 服务端验证通过后该空间记入我的本机空间清单并出现在脚本视图；凭同一密钥我拥有与创建者完全对等的读写能力（DEC-data-sync-007）
```

**场景 2：无效空间码（失败场景）**
```gherkin
Given 我拿到的空间码格式不正确、空间已被删除或密钥已不匹配
When 我尝试加入
Then 加入被拒绝并说明原因（格式错误在本机直接拦截；服务端验证失败不记入本机）
```

### 故事 3：保存脚本并维护名称、备注与版本 [US-DS-003]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者
**我希望**：把本机已导入的流程（受约束步骤树）保存为空间脚本并填写名称与备注；之后修改流程内容时保存为新版本并附版本说明
**从而**：团队共享的脚本有可辨识的信息和完整历史，出问题时能回到可用版本

**【验收标准】**

**场景 1：首次保存为脚本**
```gherkin
Given 我本机有一条已验证的流程（如"发货仓库→联系电话"联动或装箱流程）
When 我把它保存到当前空间，填写脚本名称与备注（明示内容将存储到该服务器）
Then 空间出现该脚本（脚本 ID 在本机生成；首个版本），其他参与者可见其名称、备注与版本列表；保存的是流程定义本身，不含本机运行数据或占用记录
```

**场景 2：修改步骤内容保存为新版本**
```gherkin
Given 空间已有该脚本，我在本机经「用 AI 优化」修改了对应流程的步骤树内容（如装箱流程增加一个组的处理条件）
When 修订经校验保存为未启用的本机流程
Then 同步区显示本地改动，空间版本列表暂不变化；我本人可在核对后重新启用本机修订
When 我另行选择「发布新版本」并填写本版说明
Then 服务端在写锁内分配下一个版本号，流程定义作为不可变快照保存，历史版本仍保留可查；内容 hash 与版本随实际步骤内容变化，不只随改名变化
```

**场景 3：修改名称或备注不产生新版本**
```gherkin
Given 我只想修正脚本名称或备注的笔误
When 我保存名称/备注修改
Then 脚本信息更新，不产生新版本，版本列表不变
```

### 故事 4：拉取脚本并选择使用某个版本 [US-DS-004]

**优先级**: P0

**【用户故事】**
**作为**：空间参与者
**我希望**：浏览空间脚本清单，把选定的脚本版本（流程定义）拉取到本机使用；他人发布新版本不会自动改变我本机的流程，若我显式修订本机流程则标记为本地改动
**从而**：我直接用团队验证过的脚本，无需人工传文件，且我的自动执行行为不会被别人的更新突然改变

**【验收标准】**

**场景 1：拉取并启用**
```gherkin
Given 我是空间参与者，某脚本已有若干版本
When 我查看脚本名称、备注、版本列表与内容摘要（步骤含分支/循环展开描述，保存/提交/确认类动作——含嵌套提交——显著标注），选择某版本拉取到本机
Then 该版本经扩展全量校验后进入本机并处于未启用状态；我本人启用后，本机按该版本执行（DEC-data-sync-004）
```

**场景 2：新版本仅提示不自动切换**
```gherkin
Given 我本机固定使用某脚本的版本 2，其他参与者发布了版本 3
When 我日常使用扩展（包括正在执行流程时）
Then 本机继续按版本 2 执行，进行中的运行不因同步状态变化被重启；同步区出现版本 3 可用提示，不弹窗阻塞、不自动切换（DEC-data-sync-002）
```

**场景 3：手动切换与回退**
```gherkin
Given 版本 3 在我这里出现问题，我需要回到版本 2（或从版本 2 升级到版本 3），两个版本均为受支持的流程格式
When 我在版本列表中手动选择目标版本并确认（切换前明确提示将替换本机执行版本）
Then 本机执行版本切换为我选择的版本，宿主页行为随选定版本变化；切换后的启用仍由我本人操作
```

**场景 4：拉取校验失败（失败场景）**
```gherkin
Given 某版本内容不符合流程格式或包含不支持的动作，或该版本是旧 schema（动作组格式）、含未知节点或非法引用
When 我尝试把它拉取到本机
Then 拉取被整体拒绝并说明原因（格式支持但内容非法 / 格式版本不支持分别说明），本机已有脚本与流程零写入不受影响；服务端该版本数据仍保留可查
```

### 故事 5：空间生命周期管理 [US-DS-005]

**优先级**: P1

**【用户故事】**
**作为**：空间参与者
**我希望**：在本机"忘记"不再使用的空间；必要时删除服务端上的整个空间
**从而**：本机清单保持干净；团队不再需要的共享空间可以彻底移除

**【验收标准】**

**场景 1：在本机忘记空间**
```gherkin
Given 我不再使用某空间（可能已被他人在服务端删除）
When 我确认"忘记"该空间
Then 本机移除该空间条目、其脚本关联与选中状态；本机流程与已拉取内容保留；服务端与其他参与者不受影响
```

**场景 2：删除服务端空间**
```gherkin
Given 团队不再需要该空间，我持有其密钥
When 我确认删除（文案明确提示将移除服务端全部脚本）
Then 服务端级联删除空间及其脚本，各端后续访问得到明确的 404 提示；各端本机已拉取内容与本地流程保留
```

### 故事 6：同步状态与异常可见 [US-DS-006]

**优先级**: P1

**【用户故事】**
**作为**：空间参与者
**我希望**：随时看到同步是否正常（成功/失败/服务不可达）以及失败原因
**从而**：同步出问题时我知道发生了什么，本地工作不被中断

**【验收标准】**

**场景 1：服务不可达时本地与进行中的流程不受影响**
```gherkin
Given 云端服务暂时不可用，本机可能正在执行一条流程流程（如装箱处理中）
When 我继续日常使用本机流程
Then 本地流程照常执行、进行中的运行不被同步状态变化重启或取消；同步区显示服务不可达，恢复后可继续同步
```

**场景 2：失败原因可见（失败场景）**
```gherkin
Given 我的一次保存或拉取失败（如网络中断、密钥被拒、空间已删除、版本格式不受支持）
When 我查看同步区
Then 失败条目与具体原因可见，且可以对同一操作重试（不受支持的格式版本除外——指引发布方重新发布受支持格式）
```
