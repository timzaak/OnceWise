## 用户故事

### 故事 1：在自有 AI 工具中验证网页操作并产出流程文件 [US-SSBA-007]

**优先级**: P0

**【用户故事】**
**作为**：AI 工具用户
**我希望**：把本项目提供的 Agent Skill 装入我的自有 AI 工具，按其指引配置 Chrome DevTools MCP，在目标网页上实际探索并验证我想自动化的操作，验证通过后由 AI 产出符合本项目流程格式的流程文件
**从而**：流程沟通与验证用我已有且熟悉的 AI 工具完成，扩展不需要内置 AI，我也不需要找开发者写代码

**【验收标准】**

**场景 1：受控测试页验证并产出流程**
```gherkin
Given 我已在自有 AI 工具中装入本项目 Skill，并按指引完成 Chrome DevTools MCP 配置，打开了本项目提供的受控测试页
When 我向 AI 描述"选择某仓库后把联系电话填成对应号码"，AI 在页面上实际执行并确认该操作成功，然后按流程格式产出流程文件
Then 流程文件包含站点、适用页面特征、触发条件与步骤内容等我可核对的内容（流程以受约束节点表达读取、条件、动作、等待或循环），AI 说明其中哪些操作已经过页面验证，并可随即经本机通道把流程交付扩展（见 US-NM-002）
```

**场景 2：MCP 未配置时获得明确指引**
```gherkin
Given 我的 AI 工具尚未配置 Chrome DevTools MCP
When 我请求 AI 在浏览器中验证某个网页操作
Then AI 按 Skill 指引给出具体配置步骤与命令，而不是静默失败，也不产出未经页面验证的流程
```

**场景 3：连接日常 Chrome 会话的边界**
```gherkin
Given 我想在带登录态的日常 Chrome 会话中验证真实站点操作
When 我按 Skill 指引连接我的日常浏览器
Then 每次连接都经过我本人在浏览器中的确认，页面出现受控提示标识；验证完成后我可以随时断开
```

### 故事 3：流程启用 [US-SSBA-009]

**优先级**: P0

**【用户故事】**
**作为**：AI 工具用户
**我希望**：按流程独立启用或关闭；启用时不被要求逐条审阅或首次在场验证，也没有任何按站授权的额外步骤
**从而**：扩展只在流程自带站点上运行（流程自带站点域名），流程的开关完全由我控制，启用流程没有额外摩擦

**【验收标准】**

**场景 1：一键启用后自动执行**
```gherkin
Given 一条流程经本机通道保存为未启用，导入页面正呈现「核对摘要→启用」一键确认
When 我在当前页面一键点击「启用」，无需切换到其他界面，也无需任何站点授权操作
Then 流程随即启用；我进入流程指定的页面（或由 AI 导航过去）后流程自动执行其动作，页面保持安静（无提示弹层），表单变化即执行结果；全程没有被要求做首次人工确认
```

**场景 2：未启用流程不执行**
```gherkin
Given 一条流程处于未启用（或已暂停）状态
When 我进入该流程涉及的站点页面
Then 流程不执行任何页面动作，流程清单可见其未启用状态
```

**场景 3：按流程独立开关**
```gherkin
Given 我有多条流程分别对应不同功能
When 我只启用其中一条并保持其余关闭
Then 只有已启用的流程会执行，关闭的流程不产生任何页面动作
```

### 故事 4：字段变化联动与失败原因可见 [US-SSBA-003]

**优先级**: P0

**【用户故事】**
**作为**：AI 工具用户
**我希望**：已启用的联动流程在某字段选择或输入变化后，自动读取页面状态并填写、选择或点击其他字段，出问题时可在流程详情查看失败环节
**从而**：我按原节奏工作，扩展替我完成重复填写，出问题时我能复现并知道发生在哪个环节、哪一步

**【验收标准】**

**场景 1：字段变化触发联动**
```gherkin
Given 流程"发货仓库选择后填充联系电话"已启用，我正在流程指定的页面工作
When 我把"发货仓库"切换为任一仓库
Then "联系电话"被自动填入对应值，页面保持安静无打扰，不阻塞我继续操作
```

**场景 2：失败保守中止，失败原因可查看**
```gherkin
Given 已启用流程此前正常生效
When 某次触发后执行失败（如目标字段被页面移除、读取数据无效或值核对不符）
Then 本次执行保守中止、不自动重试，也不改动我手工完成的操作；流程清单与详情可查看最近一次实际触发的失败节点、循环位置、环节与简短原因；成功后清除该失败提示
```

**场景 3：敏感值脱敏展示**
```gherkin
Given 流程内容或运行失败涉及联系电话等具体业务数据值
When 我在侧边栏查看流程或失败原因
Then 这类值以脱敏形式展示
```

### 故事 5：进入页面自动执行受约束步骤树 [US-SSBA-010]

**优先级**: P0

**【用户故事】**
**作为**：AI 工具用户
**我希望**：建立"进入某个页面后自动执行一组受约束步骤树"的流程，流程可以按页面实时状态决定每一步（读取、判断、跳过、循环、等待、校验），且它只在流程指定的页面执行
**从而**：打开常用页面后的固定业务序列（如商品装箱的逐组处理）自动完成，其他页面不受任何影响

**【验收标准】**

**场景 1：进入指定页面执行流程**
```gherkin
Given 一条进入页面流程已启用
When 我打开或刷新流程指定的页面
Then 流程按序执行，同一次页面进入内该流程只启动一次
```

**场景 2：非目标页面不执行**
```gherkin
Given 同一站点存在与目标页面内容不同的其他页面
When 我浏览这些页面
Then 流程不执行，页面上没有任何自动动作
```

**场景 3：流程中途失败保守中止**
```gherkin
Given 一条已启用流程的步骤树包含多个步骤（含循环）
When 其中某一步因元素缺失、定位歧义、校验失败或等待超时而失败
Then 已执行的步骤不回滚、剩余步骤不继续；流程清单与详情显示失败环节、节点与循环位置（如第几组）
```

**场景 4：多包装组顺序处理**
```gherkin
Given 受控装箱页有多个包装组，一条装箱流程已启用
When 我打开放置页
Then 每个包装组各处理一次（检查编辑态、勾选、加载箱规、校验行数据、保存），每组保存完成后才进入下一组；全部组成功后最终确认只执行一次并等待货件预览出现
```

**场景 5：无效箱规数据不保存不确认**
```gherkin
Given 受控装箱页某包装组的行数据存在缺失、空值、0 或非数值（或组内没有可读取的行）
When 流程处理到该组的数据校验步骤
Then 该组不被保存、后续组不被处理、最终确认不执行
```

**场景 6：保存完成信号超时不视为成功**
```gherkin
Given 流程在某组点击保存后等待可观察的保存完成信号
When 信号在截止时间内未出现
Then 执行保守停止（不把时间流逝当成成功），保存点击不被重放
```

**场景 7：声明的后续页继续执行（同站跨页）**
```gherkin
Given 一条已启用流程声明了入口页与有序的后续声明页，每页各有自己的步骤
When 流程在入口页触发后执行到其声明的跳转（由流程内的白名单点击触发）
Then 运行在到达的声明页继续执行，直到最后一页完成；同次触发整段只执行一遍
```

> 跨页完整语义（新标签页变体、页间等待超时、意外中断保守取消、跨页防重放、失败页定位）的验收标准见 [`cross-page-flow.md`](cross-page-flow.md)（US-CPF-001）。

### 故事 6：提交类动作自动执行且按业务实例防重放 [US-SSBA-004]

**优先级**: P0

**【用户故事】**
**作为**：AI 工具用户
**我希望**：流程可以包含保存、提交、确认类动作，启用后触发即自动执行；同时扩展以业务实例（如同一张单据）为单位保证这类动作不因刷新、重复触发或多标签页而重放，页面已处于目标状态时直接跳过
**从而**：包含最终提交的完整业务动作可以交给流程完成，又不会对同一单据造成重复提交

**【验收标准】**

**场景 1：提交类动作自动执行**
```gherkin
Given 一条已启用流程包含"点击保存"动作
When 触发条件满足
Then 保存动作自动执行，无需我再次确认（该动作在导入摘要中注明为提交类）
```

**场景 2：同一业务实例刷新与重复进入不重放**
```gherkin
Given 上一次运行已对某业务实例（同一张单据）执行过提交类动作，其占用记录未解除
When 我刷新页面或重复触发，扩展再次尝试处理同一业务实例
Then 该流程不再执行提交动作（该业务实例本会话内已被占用），不产生任何自动动作
```

**场景 3：已处于目标状态时跳过**
```gherkin
Given 流程执行前页面上的目标状态已经达成（如表单已保存、该组已处理）
When 触发条件满足
Then 对应提交类动作被跳过，不产生重复业务动作
```

**场景 4：多标签页只有一个执行者**
```gherkin
Given 同一业务实例在两个标签页同时满足触发条件
When 自动执行被触发
Then 同一业务实例只有一个执行者完成提交；另一侧不重复提交已发出的动作
```

> 2026-10-02：业务实例占用跨页面保持——跨页运行中断或失败后，同一单据的再次进入不重放；继续执行时复核业务标识，不同或歧义即取消（跨页防重放见 [`cross-page-flow.md`](cross-page-flow.md) US-CPF-001 场景 4/5）。

### 故事 7：查看实际触发失败原因 [US-SSBA-002]

**优先级**: P1

**【用户故事】**
**作为**：AI 工具用户
**我希望**：流程实际触发失败后，在侧边栏查看简短原因和失败节点
**从而**：知道自动执行停在何处，便于修正流程或页面

**【验收标准】**

**场景 1：实际触发失败**
```gherkin
Given 一条已启用流程在真实触发后执行失败
When 我打开侧边栏流程清单或详情
Then 我能查看该流程最近一次失败的节点、循环位置、环节和简短原因；页面没有预演入口
```

**场景 2：成功后清除旧错误**
```gherkin
Given 流程曾有失败提示
When 后续一次真实触发执行成功
Then 旧失败提示被清除，不展示执行历史
```

**场景 3：正常防重复跳过不报错**
```gherkin
Given 同一业务实例已被占用
When 重复触发被防重复机制跳过
Then 不新增失败提示
```

> 2026-10-02：跨页流程的失败明细增加页定位（失败发生在哪一页），与节点、循环位置、环节叠加（见 [`cross-page-flow.md`](cross-page-flow.md) US-CPF-001 场景 3/6）。

### 故事 8：流程管理与维护 [US-SSBA-005]

**优先级**: P1

**【用户故事】**
**作为**：AI 工具用户
**我希望**：在侧边栏看到全部流程清单，能查看、修改、暂停/恢复每条流程
**从而**：业务流程变化时我自己维护，执行出问题时可查看失败节点与循环位置，不需要开发者介入

**【验收标准】**

**场景 1：修改已启用流程的输入值**
```gherkin
Given 我有一条已启用且声明了流程输入项的流程
When 我在侧边栏打开它，修改输入值并保存
Then 下次自动运行按新输入值生效、启用状态保持
```

**场景 2：用 AI 优化已有流程**
```gherkin
Given 我有一条已启用的流程，需要修改步骤中的定位或动作
When 我在流程详情点击「用 AI 优化」
Then 原流程先暂停并取消当前执行，并授权 AI 限时读取原流程；AI 经本机通道读取现有定义、在目标页验证受影响步骤后交付修订供扩展校验，并向我说明变更和覆盖对象
When 我明确确认本次修订后 AI 经本机通道发起保存
Then 原流程按同一 ID 被覆盖且转为未启用，流程清单没有新增并行流程；只有我本人再次启用后才会执行修订内容
```

**场景 3：修订期间原流程已变化**
```gherkin
Given AI 已发起某条流程的优化流程
When 原流程在另一处被修改、重新启用或删除，而 AI 随后尝试保存修订
Then 覆盖被拒绝，当前流程内容不受影响；我可从流程详情重新发起优化
```

**场景 4：暂停取消当前执行，恢复不自动续跑**
```gherkin
Given 一条流程正在执行中（如装箱处理到第二个包装组）
When 我在清单中暂停该流程
Then 当前执行被取消（后续动作与轮询停止），已完成的组保留在页面上；之后我恢复启用，流程从头按触发条件重新执行，不从中间节点自动续跑
```

### 故事 9：首次使用说明与排除平台声明 [US-SSBA-011]

**优先级**: P1

**【用户故事】**
**作为**：AI 工具用户
**我希望**：安装扩展后首次打开始终看到使用说明，明确本产品声明不支持辅助操作的平台（如淘宝、亚马逊）不得使用，以及启用后自动执行（含保存/提交/确认）的语义与风险边界
**从而**：我清楚哪些平台和场景不该使用本产品，并自行遵守边界

**【验收标准】**

**场景 1：首次打开展示说明**
```gherkin
Given 我刚安装扩展并首次打开侧边栏
When 侧边栏加载完成
Then 使用说明完整展示支持边界、排除平台声明与自动执行语义，我确认阅读后进入主界面
```

**场景 2：说明可再次查看**
```gherkin
Given 我已越过首次说明
When 我需要重新查看边界声明
Then 侧边栏提供入口再次打开完整使用说明
```

**【备注】** 排除平台声明是产品使用边界与责任划分，不构成对第三方平台流程的事实认定，首轮不做运行时封禁（DEC-011）。
