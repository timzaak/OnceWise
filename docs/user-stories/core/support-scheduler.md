## 用户故事

### 故事 1：管理流程的定时计划 [US-SCH-001]

**优先级**: P1

**【用户故事】**
**作为**：AI 工具用户
**我希望**：在侧边栏流程工作台为流程创建、编辑和删除定时计划（每日/每周指定时刻或固定间隔，并保存入口网址）
**从而**：集中维护哪些流程在何时自动执行，不依赖逐次手动安排

**【验收标准】**

**场景 1：创建每日计划**
```gherkin
Given 流程已启用，侧边栏流程工作台已打开
When 用户为该流程创建一个"每日 09:00"的计划并保存
Then 计划出现在该流程的计划列表中，并按本机时区显示下一次触发时刻
```

**场景 2：编辑计划重排下一次触发**
```gherkin
Given 流程已有一个"每日 09:00"的活跃计划
When 用户把周期改为"每周一 09:00"并保存
Then 该计划的下一次触发时刻更新为下一个周一 09:00，历史安排不保留
```

**场景 3：删除计划即时生效**
```gherkin
Given 流程已有一个活跃计划
When 用户删除该计划
Then 计划从列表消失，原定时刻不再产生任何自动执行
```

**场景 4：计划数量达到上限**
```gherkin
Given 该设备上的定时计划数量已达到产品设定的上限
When 用户再创建一个新计划
Then 创建被拒绝并提示计划数量已达上限，既有计划不受影响
```

### 故事 2：到点自动执行 [US-SCH-002]

**优先级**: P1

**【用户故事】**
**作为**：AI 工具用户
**我希望**：已启用流程的计划到点时自动执行——已有打开的匹配标签页时在其中执行，没有时由扩展自动在前台标签页打开计划保存的入口网址并执行
**从而**：无需到点手动打开页面或操作，例行业务按时自动完成

**【验收标准】**

**场景 1：到点无匹配页面自动开页执行**
```gherkin
Given 流程已启用且有活跃的定时计划，浏览器运行中且没有该流程站点的匹配标签页
When 计划触发时刻到达
Then 扩展自动在前台标签页打开计划保存的入口网址，流程在该页面自动执行完成
And 页面以自身状态变化呈现结果（页面静默，无提示弹层），运行结束后该标签页保留
```

**场景 2：到点已有匹配页面在其中执行**
```gherkin
Given 流程已启用且有活跃计划，浏览器中已打开其入口页面的标签页
When 计划触发时刻到达
Then 流程在该标签页内自动执行，不再新开标签页
```

**场景 3：到点流程未启用零动作**
```gherkin
Given 流程有活跃计划但处于暂停或关闭状态
When 计划触发时刻到达
Then 本次不执行、零页面动作，也不记录失败提示
And 计划保留，流程恢复启用后按后续计划时刻正常触发
```

**场景 4：到点页面与流程不符不启动**
```gherkin
Given 计划保存的入口网址已改版或站点登录态过期，到点打开的页面与流程声明的页面特征不符
When 计划触发时刻到达
Then 流程不启动、零页面动作，侧边栏该流程出现一次失败提示说明页面不匹配
```

### 故事 3：错过与到点门禁失败的可见性 [US-SCH-003]

**优先级**: P1

**【用户故事】**
**作为**：AI 工具用户
**我希望**：因浏览器未运行或唤醒过迟而错过的触发、以及因输入未就绪被跳过的触发，都能在侧边栏看到提示，且系统不补跑
**从而**：我知道哪一次没有执行、为什么，且不会有延迟到来的重复执行

**【验收标准】**

**场景 1：浏览器未运行错过**
```gherkin
Given 流程有"每日 09:00"的活跃计划，09:00 时浏览器处于关闭状态
When 用户之后启动浏览器
Then 侧边栏该流程出现错过提示，该次不补跑、不自动重试
And 下一次按计划时刻正常触发
```

**场景 2：唤醒过迟错过**
```gherkin
Given 流程有活跃计划且预定触发时刻已过，扩展实际处理该次触发时已超出有限的宽限范围
When 扩展处理该次触发
Then 该次按错过处理：跳过并记录提示，随后仍按计划排下一次触发
```

**场景 3：输入未就绪跳过**
```gherkin
Given 流程声明了必填输入项且本机尚未保存有效值，流程已启用且有活跃计划
When 计划触发时刻到达
Then 本次零页面动作，侧边栏提示具体缺失或无效的输入项目
And 补齐并保存输入值后，下一次触发正常执行
```

**场景 4：成功后清除**
```gherkin
Given 侧边栏该流程存在一次错过或门禁失败提示
When 该流程下一次定时触发成功执行完成
Then 该提示被清除，不保留任何定时执行历史
```

**【备注】** 错过与门禁失败提示沿用既有会话内生命周期：浏览器重启后不再可见，不为此新建持久执行历史。

### 故事 4：定时与手动触发共用防重放 [US-SCH-004]

**优先级**: P1

**【用户故事】**
**作为**：AI 工具用户
**我希望**：定时触发的运行与手动进入页面等其他触发的运行共用同一运行互斥与业务实例防重放护栏
**从而**：同一笔业务不会因定时与手动并发、或多个计划同时到点而被重复提交

**【验收标准】**

**场景 1：业务实例已占用时定时触发跳过**
```gherkin
Given 带提交类动作的流程声明了业务实例标识，且该业务实例的占用未解除（前次运行失败或结果未知）
When 计划触发时刻到达
Then 本次定时触发被跳过并说明原因，零页面动作，不重复提交
```

**场景 2：定时与手动并发只有一个执行者**
```gherkin
Given 流程有活跃计划，且在计划触发时刻用户正手动进入该流程的入口页面
When 定时触发与页面进入触发在同一业务实例上同时就绪
Then 只有一个运行执行，该业务实例的提交类动作至多执行一次
```

**场景 3：多计划同时到点各自独立串行**
```gherkin
Given 同一设备上多个计划的触发时刻相同（同一流程或同站不同流程）
When 该时刻到达
Then 各计划作为独立运行分别启动，同一业务实例按占用串行，不同业务实例互不阻塞
```

**场景 4：定时触发的跨页流程照常续跑**
```gherkin
Given 已启用的同站顺序跨页流程有活跃计划
When 计划触发时刻到达
Then 运行按声明的页序自动跨页连续完成，防重放与失败可见语义与手动触发一致
```

### 故事 5：计划归属创建设备 [US-SCH-005]

**优先级**: P1

**【用户故事】**
**作为**：AI 工具用户
**我希望**：定时计划保存在创建它的设备本机，不随同步空间分发（流程本体照常同步）
**从而**：每台设备按自己的计划独立触发；同一计划只在其创建设备上到点，不会随流程复制到多台设备同时触发（各设备自建的计划之间不协调、不去重）

**【验收标准】**

**场景 1：他设备拉取流程不带计划**
```gherkin
Given 设备 A 为某流程创建了活跃计划，设备 B 经同步空间拉取了同一流程
When 计划触发时刻到达
Then 设备 A 按计划触发执行
And 设备 B 无该计划、不产生任何定时动作，其流程清单也不显示设备 A 的计划
```

**场景 2：删除流程清理本机计划**
```gherkin
Given 设备上某流程存在活跃计划
When 用户在该设备删除该流程
Then 该流程的计划随之清理，原定时刻不再触发
```

**场景 3：计划不进入流程定义**
```gherkin
Given 用户为流程创建过计划
When 该流程经同步空间发布或做版本比较
Then 共享与比较的流程内容不包含任何计划信息，计划不影响流程版本
```
