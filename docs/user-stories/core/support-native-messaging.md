> 关联：[正式 PRD](../../prd/core/support-native-messaging.md)。

## 用户故事

### 故事 1：安装本机流程交接环境 [US-NM-001]

**优先级**：P0

**【用户故事】**

**作为**：AI 工具用户（详见 [`docs/user-stories/_roles.md`](../_roles.md)）
**我希望**：按 Skill 指引让 AI 在我的电脑（Windows、macOS 或 Linux）上安装 OnceWise 本机交接程序，并验证它与我的 Chrome 中扩展的真实连接
**从而**：流程可以不经浏览器导入页的逐控件操作直接进入扩展，且我在交付流程前就知道交接环境是否就绪

**【验收标准】**

**场景 1：安装并验证连通**

```gherkin
Given 我使用 Windows、macOS 或 Linux 桌面 Chrome，并已安装 OnceWise 扩展
When 我按 oncewise-setup 的指引让 AI 完成本机交接程序的安装
Then AI 完成与扩展的连通验证，并向我报告真实结果（包括所绑定的浏览器与扩展）；此后流程交付可经本机通道进行
```

**场景 2：未就绪时获得明确指引而非假象**

```gherkin
Given 本机交接程序未安装、文件被移动，或扩展未在运行
When AI 尝试经本机通道交付流程
Then 交付明确失败并说明原因（例如需要先完成安装步骤），不产生"已保存"的假象；AI 按指引带我修复后重试
```

**场景 3：卸载不影响扩展其余功能**

```gherkin
Given 我已安装本机交接程序但不再需要本机通道
When 我按指引卸载它
Then 卸载完成后，扩展的流程执行、管理和同步功能不受影响
```

### 故事 2：新流程经本机通道交付并核对摘要 [US-NM-002]

**优先级**：P0

**【用户故事】**

**作为**：AI 工具用户（详见 [`docs/user-stories/_roles.md`](../_roles.md)）
**我希望**：AI 在目标网页验证通过后，把流程经本机通道交给扩展校验，在对话中取得我对本次内容的明确确认后保存，并让我在扩展中核对保存结果
**从而**：从验证到流程进入扩展没有浏览器导入页的逐控件操作，进入扩展的流程仍经过统一校验，且不会立即生效

**【验收标准】**

**场景 1：交付成功并默认关闭**

```gherkin
Given AI 已在目标网页验证操作并产出流程文件，本机交接环境已就绪
When AI 经本机通道把流程交给扩展
Then 扩展完成全量校验（结构、控制流语义与预算）并给出可读摘要（站点、适用页面、触发条件、步骤；提交类动作显著标注）；AI 向我说明本次内容与验证范围并等待我明确确认
When 我在对话中确认本次内容后，AI 经本机通道发起保存
Then 流程保存为未启用状态，AI 不能代替我启用；扩展随即呈现一键「启用」确认，由我本人操作（见 US-SSBA-009）
```

**场景 2：未确认或要求修改时不保存**

```gherkin
Given 扩展已校验流程并给出摘要，但我尚未确认本次内容，或要求继续修改
When AI 准备保存流程
Then AI 不发起保存；内容修改后需重新校验、重新说明摘要并再次等待我确认
```

**场景 3：校验失败被整体拒绝**

```gherkin
Given 流程文件缺失关键内容、包含不支持的动作或节点、非法变量引用、超出预算，或携带未知 schemaVersion
When 该流程经本机通道被交付
Then 交付被整体拒绝并说明具体原因，不保存任何部分，我已有流程不受影响
```

### 故事 3：修订已有流程经本机通道交付 [US-NM-003]

**优先级**：P0

**【用户故事】**

**作为**：AI 工具用户（详见 [`docs/user-stories/_roles.md`](../_roles.md)）
**我希望**：从流程详情发起「用 AI 优化」后，AI 经本机通道读取现有流程定义、在目标页验证受影响步骤并交付修订，在对话中取得我的明确确认后保存
**从而**：既有流程的维护不退回浏览器导入页的逐控件操作，且修订不会静默覆盖期间发生的新变化

**【验收标准】**

**场景 1：修订按原 ID 覆盖并转为未启用**

```gherkin
Given 我从流程详情发起「用 AI 优化」，原流程已暂停并取消当前执行
When AI 经本机通道读取现有定义、在目标页验证受影响步骤后交付修订
Then 扩展按同一校验给出修订摘要，AI 向我说明变更内容与覆盖对象并等待我明确确认
When 我在对话中确认本次修订后，AI 经本机通道发起保存
Then 修订以原流程 ID 覆盖并转为未启用，流程清单没有新增并行流程；只有我本人再次启用后才执行修订内容
```

**场景 2：修订期间原流程已变化时拒绝覆盖**

```gherkin
Given AI 已发起某条流程的优化流程
When 原流程在另一处被修改、重新启用或删除，而 AI 随后尝试保存修订
Then 覆盖被拒绝，当前流程内容不受影响；我可以从流程详情重新发起优化
```

**场景 3：放弃修订**

```gherkin
Given 我从流程详情发起优化，原流程已暂停，AI 已说明修订摘要
When 我拒绝替换或结束本次修订
Then 修订候选不覆盖原流程，原流程保持暂停，是否重新启用仍由我决定
```

### 故事 4：交接结果真实可见 [US-NM-004]

**优先级**：P0

**【用户故事】**

**作为**：AI 工具用户（详见 [`docs/user-stories/_roles.md`](../_roles.md)）
**我希望**：每次本机通道交接都返回真实结果——成功、失败或连接断开都如实呈现，保存结果以扩展中的真实状态为准
**从而**：我不会在流程未保存时误以为已保存，也不会基于假成功去启用或依赖不存在的流程

**【验收标准】**

**场景 1：成功结果与扩展状态一致**

```gherkin
Given AI 已在对话中取得我对本次内容的明确确认，并经本机通道发起保存
When 扩展向我展示保存结果，AI 向我报告本次交接结果
Then 两处结果与扩展中该流程的真实状态一致（可从扩展读回核对），不夸大也不遗漏拒绝原因
```

**场景 2：断线或无响应时结果未确认**

```gherkin
Given 保存请求发出后通道断开，或超出期限未收到扩展的明确结果
When AI 向我报告本次交付
Then AI 如实报告结果未确认并说明可能原因（未安装、连接断开、扩展未运行），不把无响应当作保存成功；重试前先核对扩展中流程的真实状态
```

### 故事 5：查看本地历史并回滚 [US-NM-005]

**优先级**：P0

**【用户故事】**

**作为**：AI 工具用户（详见 [`docs/user-stories/_roles.md`](../_roles.md)）
**我希望**：在流程详情查看最近保存的版本，并自行选择旧版本回滚
**从而**：流程优化后若发现问题，可以恢复我此前保存过的内容。

**【验收标准】**

**场景 1：查看并回滚**

```gherkin
Given 某条流程在本机有多个成功保存版本
When 我在扩展流程详情选择其中一个旧版本并确认回滚
Then 当前流程恢复所选版本的内容并处于未启用状态，我能核对回滚结果，只有我本人再次启用后才执行
```

**场景 2：历史上限与失败保护**

```gherkin
Given 某条流程已连续成功保存超过 10 个版本
When 我查看该流程的本地历史，或选择一个可用旧版本回滚
Then 只显示最近 10 个成功保存版本；回滚失败时当前流程不被部分改写，已有可用历史仍保留
```
