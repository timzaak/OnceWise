# 脚本同步与空间协作（data-sync） 产品需求文档 (PRD)

**创建时间**: 2026-09-25
**优先级**: P0
**发布时间**: 2026-09-25（2026-09-25 修订：去账号化空间模型 + 本地优先存储；2026-09-26 修订：同步对象为流程定义，DEC-data-sync-011）

> 本 PRD 是 self-service-browser-automation 的能力扩展（DEC-data-sync-001）：定位小范围真实使用，自建轻量云端服务，把脚本同步给多人协作使用。它改变了 self-service-browser-automation 的两条既有边界——"流程等本机数据全部保存在用户本机浏览器存储内，不上传"与 Out of Scope 中的"流程共享、团队协作"；该范围扩大由用户于 2026-09-25 主动发起，行使 `DEC-self-service-browser-automation-008` 的重开条件，对应章节已在 self-service-browser-automation 正式 PRD 中同步修订。
> 2026-09-25 用户修订（DEC-data-sync-007 / 008）：服务端保持极简，**取消账号体系**——空间 ID 与访问密钥全部在客户端本地生成，服务端只按密钥寻址存储；**整个存储体系本地优先（local-first）**，本机浏览器存储是数据主体，云端同步是显式、次级的分享通道。原 workspace/成员/邀请模型（DEC-data-sync-003）被取代。
> **2026-09-26 修订（DEC-data-sync-011）**：同步对象明确为 **受约束步骤树定义**（随 ssba DEC-019）——脚本版本是流程的不可变快照；内容摘要需覆盖分支、循环与嵌套的提交类动作；运行期 context、DOM 数据、运行快照与本机占用记录不同步；非当前格式或含不支持能力的版本在拉取/切换时整体拒绝且零写入，不做静默迁移；「可回退任一历史版本」限定为当前扩展支持的格式，不支持格式的版本数据仍保留在服务端。
> 术语约定：**脚本 = 自动化流程进入同步空间后的称呼**，数据格式与安全语义同流程（仍是结构化数据，不是代码）；**空间（space）= 一个由 `空间ID#密钥` 寻址的脚本存放地**。

## 1. 相关用户故事

> 详细故事与验收标准见 [`docs/user-stories/core/data-sync.md`](../../user-stories/core/data-sync.md)；角色定义（含本 feature 的空间参与者）见 [`docs/user-stories/_roles.md`](../../user-stories/_roles.md)。

### 1.1 相关故事
- `[US-DS-001]` 配置同步服务并创建空间，优先级 P0，来源 `docs/user-stories/core/data-sync.md`
- 角色：空间参与者（创建者）

- `[US-DS-002]` 凭空间码加入空间，优先级 P0，来源同上
- 角色：空间参与者（加入者）
- 摘要：同事把"空间码"（`空间ID#密钥`）发给使用者，粘贴即加入；服务端验证通过后才记入本机

- `[US-DS-003]` 保存脚本并维护名称、备注与版本，优先级 P0，来源同上
- 角色：空间参与者
- 摘要：本机流程保存为空间脚本（名称+备注），脚本 ID 本地生成；流程内容变更保存为不可变新版本；改名改备注不产生新版本

- `[US-DS-004]` 拉取脚本并选择使用某个版本，优先级 P0，来源同上
- 角色：空间参与者
- 摘要：浏览脚本与版本列表，选定版本拉取到本机（默认未启用）；本地固定所选版本，新版本仅提示；手动切换/回退

- `[US-DS-005]` 空间生命周期管理（忘记/删除），优先级 P1，来源同上
- 角色：空间参与者
- 摘要：在本机"忘记"空间（仅移除本机条目与关联）或删除服务端空间（级联删除脚本）；本机已拉取内容与本地流程一律保留

- `[US-DS-006]` 同步状态与异常可见，优先级 P1，来源同上
- 角色：空间参与者
- 摘要：同步成功/失败/服务不可达状态与失败原因可见、可重试；服务不可达不影响本地执行

既有能力引用（不重复建故事）：脚本的流程内容沿用已发布 US-SSBA-007/008 的产出与校验语义；拉取后的启用沿用 US-SSBA-009（一键启用在导入页面，同步拉取场景在侧边栏完成同等确认）。

## 2. 范围界定

### 2.1 包含功能
- **自建轻量云端同步服务**：按空间密钥寻址的脚本与版本存储分发能力；仅存储与分发结构化脚本数据，不在云端生成或执行流程（DEC-data-sync-001、DEC-data-sync-004）
- **无账号模型（DEC-data-sync-007）**：服务端没有用户、密码、令牌、成员与角色表；空间 ID（`sp-` + 16 位 base62）与访问密钥（32 位 base62）全部由客户端生成，服务端只保存密钥的 SHA-256 哈希；ID 重复注册同密钥幂等、异密钥拒绝
- **空间创建与凭码加入**：任何使用者创建空间即持有其密钥；把"空间码"（`空间ID#密钥`）经现有渠道发给同事，粘贴即加入（服务端验证通过后本机才记录）；持有同一密钥的设备权限完全对等（读、写、改名、发布、删除）
- **本地优先存储（DEC-data-sync-008）**：本机浏览器存储是全部数据（流程、已拉取脚本、空间清单与固定版本）的主体；不配置服务器、不加入任何空间时全部功能照常；云端只是显式操作（保存为脚本 / 发布版本 / 拉取）触发的分享与分发通道
- **脚本信息模型**：名称、备注、版本列表；脚本 ID 客户端生成（`sc-` + 16 位 base62）；每个版本为**流程定义**的不可变快照（DEC-data-sync-011；不含运行期 context、DOM 数据、运行快照或本机占用记录），版本号由服务端在写锁内串行分配（MAX+1）；版本可附版本说明（DEC-data-sync-002 的配套载体）
- **上传（本机 → 空间）**：把本机已导入的流程保存为脚本首个版本；流程内容变更后保存为新版本；名称/备注修改即时生效且不产生新版本；并发发布各自成为独立版本
- **拉取与版本选择（空间 → 本机）**：参与者浏览全部脚本的名称/备注/版本列表/内容摘要（摘要覆盖流程的分支、循环与嵌套提交类动作）；选定版本拉取到本机，经扩展同一全量结构校验（结构 + 控制流语义 + 预算），进入本机即未启用（DEC-data-sync-004）；旧 schema 或不支持能力的版本整体拒绝且零写入
- **本地版本固定**：他人发布新版本仅呈现可用提示，不自动改变本机流程；本机选定的版本作为当前云端基线。用户显式优化本机流程时形成未发布的本地修订，保存后未启用，只有本人重新启用才按修订内容执行；发布新版本是后续独立操作。可手动切换或回退到受支持的版本（DEC-data-sync-002、DEC-data-sync-011）
- **同步状态与异常反馈**：保存/拉取的成功、失败与失败原因可见、可重试；服务不可达时本地流程执行不受影响

### 2.2 不包含功能 (Out of Scope)
- 账号体系及一切衍生能力：注册登录、密码找回、第三方 OAuth、会话令牌、成员管理、角色分级、邀请码（DEC-data-sync-007 取消既有模型；原 DEC-data-sync-003 被 supersede）
- 流程启用状态的云端同步或跨机漫游（本机安全边界，DEC-data-sync-004）
- 自动跟随最新版本、自动升级、发布审核流（DEC-data-sync-002 已定为本地固定 + 手动切换）
- 密钥找回：本机丢失空间码即失去该空间访问权（轻量定位的明示取舍；服务端无恢复渠道）
- 历史版本的编辑或删除（版本不可变，不做版本裁剪管理）
- 多人实时协同编辑同一版本（并发发布各自成为独立版本即可）
- 对外开放运营：公测、商业发布、定价、安全合规审计与认证（DEC-data-sync-001 小范围定位）
- 云端生成或执行流程、云端 AI 能力；执行始终发生在本机扩展
- 移动端与非 Chrome 浏览器
- 既有 AI 实时导入通道（DEC-SSBA-015）的行为变更；同步通道独立并存，不改变导入通道产品语义

### 2.3 依赖项
- self-service-browser-automation 已发布能力：流程数据格式与 schema 版本机制、全量结构校验、导入摘要、启用流程（拉取通道复用同一校验与安全语义）
- 自建同步服务：团队自行部署运维并保证参与者可达（轻量自建定位，部署与备份说明随服务交付；单二进制 + SQLite，环境变量配置）
- 扩展同步交互入口与服务通信能力（host 权限随扩展安装统一获得，无需逐服务器授权）
- 参与者之间以现有渠道（IM 等）传递空间码；产品不内置通知系统

## 3. 需求概述

### 3.1 功能描述
现有扩展把用户验证过的网页操作固化为单机浏览器内的流程——本机即数据主体（local-first），无服务器也完整可用。data-sync 在此之上提供一个极简的自建云端同步服务与"空间"协作模型：使用者在本机生成空间 ID 与密钥、在服务端注册空间，把空间码发给同事；任何人凭码加入后，各方都能把本机流程保存为空间脚本（名称、备注、脚本 ID 本地生成），流程内容变更以不可变版本累积；其他参与者浏览脚本、选定版本拉取到本机，经同一校验后默认未启用，由本人启用后按该版本执行。他人发布新版本只提示，不自动改变本机内容；本机显式优化产生的未发布修订另行标记，切换与回退手动完成。服务端无账号无角色：持有密钥即持有对等访问权，配合小范围互信团队使用。

### 3.2 关键特性
- **服务端极简、无账号（DEC-data-sync-007）**：ID 本地生成、密钥哈希存储、按 `X-Space-Key` 头寻址；没有用户/令牌/成员/邀请任何一张表
- **本地优先（DEC-data-sync-008）**：本机存储是数据主体；同步是显式次级通道——"忘记空间"、断网、换服务器都不影响本地流程与已拉取内容
- **脚本仍是数据不是代码**：云端只存储与分发结构化流程数据（版本化快照），不生成、不执行；沿用既有流程 schema 的版本机制
- **本地版本固定**：他人发布新版本不改变我的执行；本机对已关联流程的显式修订显示为本地改动，不自动发布；切换与回退手动完成
- **同步不降低安全边界**：拉取的脚本经同一全量校验、进入本机即未启用；启用仅限本机用户本人；启用状态不出本机
- **单机闭环不受影响**：同步只是附加入口，从不配置服务器的用户全部既有功能照常

## 4. 业务流程与状态

### 4.1 业务流程
- **脚本 = 流程的云端表达**：同一结构化数据格式（受约束步骤树定义，DEC-data-sync-011）；云端存储与分发不改变"数据不是代码"原则，超出现有流程词汇表达力的内容同样不得进入脚本
- **数据上云边界（本 feature 的明示变化）**：脚本数据（名称、备注、版本化流程定义，含其中的联系电话等业务值）存储于自建服务器；展示层沿用敏感值脱敏流程，脱敏不改变存储内容（DEC-data-sync-001）。**不上云清单**：运行期 context、DOM 读取数据、XState 运行快照与本机业务实例占用记录一律留在本机（DEC-data-sync-011）
- **空间寻址流程（DEC-data-sync-007）**：空间由 `空间ID#密钥` 唯一寻址；ID 与密钥均在客户端 CSPRNG 生成；服务端保存密钥 SHA-256 哈希并常数时间比对；同 ID 同密钥重复注册幂等（设备重装），异密钥注册拒绝（409）；无密钥或错误密钥一律 401，不泄露空间是否存在
- **权限流程**：持有空间密钥的设备权限完全对等（浏览、拉取、发布版本、改名、删除空间）；无逐脚本权限、无角色分级——互信小圈子定位（DEC-data-sync-007 取代 DEC-data-sync-003 的两级角色模型）
- **本地空间清单**：本机已知的空间列表（ID+密钥+名称）只存在本机浏览器存储；服务端不记录"谁"持有空间；更换服务器地址清空本机空间清单与关联（本地流程保留）
- **版本不可变**：流程定义变更只能追加新版本（版本号由服务端写锁内 MAX+1 串行分配，严格递增），历史版本不可改写、不可删除；名称与备注是脚本级信息，修改即时生效且不产生新版本；并发发布各自成为独立版本
- **本地版本固定（DEC-data-sync-002）**：没有本地修订时按参与者选定版本执行；新版本仅呈现可用提示（非阻塞），不自动切换、不自动升级。本机显式修订已关联流程后，固定版本仍作为云端基线，修订内容只保存在本机且转为未启用；本人重新启用后才按本地修订执行，发布新版本后固定版本才随发布结果更新。切换与回退由本人手动确认完成，切换前明确提示将替换本机执行版本
- **拉取即未启用（承接 DEC-SSBA-014/015 安全条款）**：从空间拉取或切换版本的脚本，一律经扩展全量结构校验（结构 + 控制流语义 + 预算），通过后以未启用状态保存；校验失败整体拒绝并说明原因，本机已有数据不受影响；启用只能由本机用户本人操作，云端不能代为启用
- **格式支持边界（DEC-data-sync-011）**：拉取/切换仅接受当前扩展支持的流程格式（受约束步骤树）；非当前格式或含不支持能力的版本整体拒绝且零写入（不做静默迁移、不降级展开），服务端该版本数据仍保留可查；"回退任一历史版本"以此支持范围为限
- **不同步清单（DEC-data-sync-004）**：流程启用状态属于本机，不进入云端；执行始终发生在本机扩展
- **本地优先韧性（DEC-data-sync-008）**：云端服务不可达不影响本机任何既有功能；同步失败可见原因并可重试

### 4.2 关键状态与异常
- 同步配置状态：未配置服务器 / 已配置（可达 / 不可达 / 未检测）
- 本机空间状态：空间清单（本地记忆）；当前选中空间；"忘记"（仅本机移除）与"删除"（服务端级联删除）是两个不同操作，均需确认
- 脚本版本状态：仅追加（无编辑、无删除）；本机视角另见"本地使用状态"
- 本地使用状态：本地选定云端版本（无本地修订时的执行依据）+ 本地改动标记（如有）+ 可用新版本提示（如有）；修订、切换或回退后仍需本人确认启用
- 同步操作状态：成功 / 失败（原因可见，可重试）/ 服务不可达（本地功能不受影响）
- 异常与兜底：
  - 空间码格式不合法 → 本机直接拒绝，不发起网络请求
  - 空间码服务端验证失败（空间不存在 / 密钥错误）→ 拒绝并说明，本机不记录该空间
  - 拉取版本内容校验失败（含未知 schemaVersion、未知节点、非法引用、越界预算）→ 整体拒绝并说明原因，本机已有脚本与流程不受影响（零写入）
  - 他人发布的脚本内容超出流程词汇表达力 → 校验阶段拒绝进入本机，空间内该版本保留（云端不判断内容好坏，只做存储分发；格式校验由本机把关）
  - 脚本 ID 冲突（极小概率全局碰撞）→ 服务端 409 拒绝，客户端重新生成
  - 切换版本后未启用 → 脚本不执行，按既有侧边栏状态提示呈现
  - 服务不可达 / 网络中断 → 本地执行照常，同步区展示状态，恢复后可继续
  - 空间被他人删除 → 本机访问得到 404 明确提示；本机已拉取内容与本地流程保留，同步停止

## 5. 功能需求

### 5.1 核心需求
- **FR1 服务器配置**：侧边栏同步区配置自建服务器地址（origin 权限经用户手势授予）；换地址清空本机空间与关联（DEC-data-sync-005 的无登录版：不配置即不同步，本地全部可用）
- **FR2 空间创建与凭码加入（DEC-data-sync-007）**：一键创建空间——ID 与密钥在本机 CSPRNG 生成、注册成功后记入本机并选中；粘贴空间码加入——服务端验证通过才记入本机；空间码在同步区可查看与复制
- **FR3 空间生命周期**：本机"忘记"（移除本机条目、关联与选中，服务端不动）与服务端"删除"（级联删除空间及脚本，各端后续访问 404）均为显式确认操作
- **FR4 脚本上传与信息维护**：本机流程保存为脚本（脚本 ID 本地生成；名称、备注、首版本）；已关联流程在本机优化后显示本地改动，不自动上传，用户可另行发布为新版本并附版本说明；名称/备注修改即时生效不产生新版本
- **FR5 脚本与版本浏览**：参与者可浏览全部脚本的名称、备注、版本列表、版本说明与内容摘要（摘要覆盖流程分支、循环与嵌套的提交类动作，保存/提交/确认类动作显著标注沿用）
- **FR6 版本拉取与本地固定**：选定版本拉取到本机，经同一全量校验（结构 + 控制流语义 + 预算），进入本机即未启用；本机执行固定于所选版本（DEC-data-sync-002、DEC-data-sync-004）
- **FR7 新版本提示与切换/回退**：他人发布新版本呈现非阻塞提示；可手动切换或回退版本，切换前明确提示影响；可切换/回退的范围为当前扩展支持的格式，不支持格式的版本禁止拉取（校验错误可见）且数据保留
- **FR8 同步状态与异常反馈**：保存/拉取状态与失败原因可见、可重试；服务不可达时提示且本地功能不受影响

### 5.2 验收目标
1. **协作闭环可走通**：两名真实参与者在同一空间——A 把本机流程保存为脚本（名称/备注），修改后发布第 2 版；B 看到脚本与新版本提示，本机仍按版本 1 执行不受影响，手动切换到版本 2，经校验、本人启用后按版本 2 执行
2. **空间码闭环可走通**：A 创建空间并把空间码发给 B → B 粘贴加入 → 浏览脚本 → 拉取版本到本机启用使用；全程无需注册登录、无需开发者介入
3. **安全边界不回退**：拉取/切换的脚本进入本机一律未启用，启用仅本机本人可操作；启用状态不出现在云端任何界面
4. **版本可追溯可回退**：任一脚本版本列表完整、说明可见；回退到受支持的历史版本后本机按该版本执行；不支持的旧格式版本保留在服务端且拒绝拉取（零写入）
5. **离线韧性（local-first）**：服务不可达期间本机流程照常执行、无报错干扰；"忘记"空间与更换服务器后本机流程与已拉取内容保留；恢复/重新配置后同步可继续；运行中的流程执行不因同步状态变化被重启
6. **单机无感**：从不配置服务器的用户升级后既有功能与首启流程不变（同步仅作为附加入口出现）

## 6. API 相关约束

**适用性**: 适用（能力边界与兼容性）

- **接口能力范围**：本 feature 引入自建云端服务，对外能力范围限定为——空间注册/读取/删除、脚本与版本的存储与分发、健康探针；不提供账号认证、云端流程生成、云端执行或页面代理能力。具体端点与数据契约由技术设计文档承载，不在本 PRD 展开
- **访问控制原则**：空间数据凭 `X-Space-Key` 请求头携带的密钥访问；服务端保存密钥哈希并常数时间比对；错误密钥 401、未知空间 404，不提供存在性探测；无成员、角色与邀请概念（DEC-data-sync-007）
- **ID 与版本号契约**：空间 ID 与脚本 ID 由客户端生成（服务端校验形状）；版本号由服务端在 BEGIN IMMEDIATE 写事务内 MAX+1 串行分配（并发发布不覆盖、不错号）；统一错误体 `{"error":{"code","message"}}`；未上线不设 API 版本前缀与兼容承诺，接口路径不带版本号
- **数据边界**：上云数据仅限脚本数据（名称、备注、版本化流程定义）；启用状态、运行期 context、运行快照与本机占用记录不上云（DEC-data-sync-004、DEC-data-sync-011）；数据明示存储于自建服务器（DEC-data-sync-001）
- **兼容性原则**：脚本版本内为流程格式的不可变快照，沿用既有 schema 版本机制；本机按当前支持的 schema 版本校验（DEC-data-sync-011），拉取/切换不支持格式的版本整体拒绝且零写入，不做格式迁移——服务端对 `flowContent` 仍为不透明 JSON 存储，历史版本数据保留、可追溯，但不再可进入本机执行

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：扩展侧边栏「同步」页签承载全部同步交互——服务器地址配置、空间清单（创建/凭码加入/选中/忘记/删除/空间码复制）、脚本清单、版本列表与选择、新版本提示、同步状态；既有导入页面维持 AI 实时导入职责不变；同步拉取的摘要确认与版本选择在侧边栏完成
- **同步不强制**：未配置服务器时同步页签仅呈现配置引导，本地流程功能全部可用、首启流程不变（DEC-data-sync-005）
- **关键交互**：拉取或切换版本前可见脚本名称、备注、版本说明与内容摘要（提交类动作显著标注）；切换/回退前明确提示将替换本机执行版本；"忘记空间"与"删除空间"需确认操作，且文案明确区分本机移除与服务端删除
- **状态反馈**：同步成功/失败/服务不可达与失败原因在同步区可见、可重试；新版本提示为非阻塞展示，不打断用户当前操作
- **数据可见性**：脚本内容与摘要中敏感值沿用脱敏展示流程
- **国际化**：扩展 UI 以英语为主语言（en 为默认 catalog），内置 zh 完整翻译；同步区文案同受 i18n 覆盖
- **兼容性**：沿用既有 Chrome 扩展兼容基线（Chrome 114+）
