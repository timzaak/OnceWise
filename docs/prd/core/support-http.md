# 流程 HTTP 上报数据采集（support-http） 产品需求文档 (PRD)

**创建时间**: 2026-11-02
**优先级**: P1
**发布时间**: 2026-11-02

> 本 PRD 是基线 [`core/self-service-browser-automation.md`](self-service-browser-automation.md) 受约束步骤树的词汇增量：新增「上报请求」步骤类型——流程运行中把已采集的页面数据发送到流程文件声明的 https 服务器端点，并可把服务端返回内容捕获为数据供后续步骤使用。基线 §4.1「数据边界」（页面数据仅在本机内存出现的条款）由本能力打开限定例外，§6 网络表述已同步修订（见基线头部 2026-11-02 修订注）。
> 隐私政策、数据用途问卷、host 权限理由与商店页描述随本能力同步更新：出网目的地从"仅同步服务器"扩展为"同步服务器 + 用户流程声明的上报端点"（见 [`docs/privacy-policy.md`](../../privacy-policy.md) 与 [`docs/store-listing/privacy-declarations.md`](../../store-listing/privacy-declarations.md)）。
> 上报配置（目的地、方法、负载模板、凭据引用名）全部来自流程文件，由外部 AI 按格式产出、经本机通道交付；凭据值为本机具名记录，不同步。运行安全全部沿用既有管线（单运行锁、业务实例占用、输入门禁、保守中止、执行预算、跨页续跑）。

## 2. 范围界定

### 2.1 包含功能
- **上报请求步骤（词汇增量）**：受约束步骤树新增上报请求节点——目的地为流程文件内声明的常量 https 网址；方法限于封闭集 GET/POST；上报负载以结构化引用组织（引用运行期读取的页面数据与流程输入值），不引入表达式或代码；节点声明期望成功状态区间（2xx）与可选响应捕获
- **执行语义沿用既有管线**：上报请求是带副作用的步骤，进入单运行锁、业务实例占用（流程声明时）、执行预算（计入节点数与运行时长，单次上报等待有硬上限）与保守中止：非成功状态、网络不可达、等待超时、响应超限或凭据缺失 → 失败中止、不自动重试、已发生操作不回滚；三类触发（字段变化、进入页面、定时）均可用，触发去抖与防连锁照旧
- **响应捕获（可选声明）**：上报成功后可把大小受限的服务端返回内容捕获为流程数据，供后续条件、断言与值引用；捕获内容只作为数据消费，扩展不解析执行返回内容中的任何逻辑
- **设备本机具名凭据**：上报认证凭据为「名称 + 请求头名 + 值」的具名记录，保存在本机（扩展内录入与管理），运行时以「请求头名: 值」单个请求头附载到上报请求；流程文件只写凭据引用名；头名与值都不进流程定义与版本历史、不随同步空间分发、不出现在摘要与失败提示中；运行时引用的凭据缺失或无效 → 该次运行保守中止并提示具体凭据名，不静默跳过、不产生外发
- **外发可见性与确认**：保存摘要对每个上报步骤做外发级标注（与提交类动作同级显著），展示目的地网址、上报数据来源与凭据引用名；流程清单对含上报步骤的流程显示外发标注；启用仅限用户本人，沿用基线启用管线
- **格式与校验**：上报节点进入交付全量结构校验（网址协议、方法封闭集、负载引用合法性、凭据引用名为合法标识、响应大小上限与预算合规）；上报节点为流程格式的词汇增量，schemaVersion 保持不变，流程格式文档随上报节点同步更新（与扩展校验器同一事实源）；不识别该节点的扩展版本对含上报节点的文件整体拒绝（效果等同版本拒绝）；携带非当前 schemaVersion 的文件整体拒绝、不迁移（沿用基线规则）
- **隐私与商店声明更新（发布依赖）**：隐私政策（出网目的地扩展、凭据本机存储、外发数据不持久化）、数据用途问卷与 host 权限理由如实更新（页面数据出网范围覆盖用户流程声明的上报端点）、商店页描述补显著能力披露（对应 CWS Limited Use 与披露要求）——材料更新完成是发布门槛

### 2.2 不包含功能 (Out of Scope)
- 流程文件内嵌明文凭据（含 URL 携带长期令牌的写法）——凭据只走本机具名引用
- http 明文上报端点——仅 https（对应 CWS 安全传输要求）
- GET/POST 之外的方法、URL 模板（目的地必须是流程内常量）、流程级请求头自定义（请求头名只存在于本机凭据记录）
- 上报自动重试、轮询、定时批量补发——失败保守中止，只会少发不会多发
- 文件上传/下载、二进制负载、流式响应
- 经 oncewise-ai-sync 或任何开发者运营服务代理、转发或存储上报内容——上报直达流程声明的端点，扩展不运营上报网络服务
- 独立于流程运行的手动外发动作（如侧边栏"立即发送"）——上报只作为流程步骤存在
- 上报/执行历史持久化——失败提示沿用会话内最近一次通道，成功后清除
- 跨站数据聚合上报——单流程单站点边界不变，上报内容限于该次运行采集的数据与输入值
- 新增 manifest 权限——上报使用既有 host 权限，`permissions`/`host_permissions` 零变更

### 2.3 依赖项
- 基线受约束步骤树运行管线（单运行锁、业务实例占用、输入门禁、保守中止、执行预算、跨页续跑）——上报是新增步骤类型，不另建运行机制
- AI 本机通道交付与全量校验（上报节点进入同一校验器；流程格式文档与校验器保持同一事实源）
- CWS 发布流程——隐私政策、数据用途问卷、权限理由与商店描述更新须随版本提交完成，未完成不发布
- 验收用受控 https 接收端（本地测试设施，承载状态断言、失败与响应捕获场景）

## 3. 需求概述

### 3.1 功能描述
用户把验证过的操作固化为流程后，采集到的数据仍留在页面与本机内存——用户希望在自己的服务器上接收这些数据做进一步处理。本能力允许 AI 在流程文件中声明上报请求步骤：流程运行到该步骤时，把此前读取的页面数据（与流程输入值）按声明的负载模板发送到流程内声明的 https 端点；上报成功即继续，服务端返回内容可被捕获为数据供后续判断，失败则保守中止并可见。上报服务器的认证凭据以具名记录保存在本机，流程只按引用名使用，不随共享泄漏。每次外发在保存摘要与流程清单中显著可见，启用仅由用户本人完成；隐私政策与商店声明如实披露该能力。

### 3.2 关键特性
- **数据出边界的唯一例外，其余不变**：页面数据仅在执行流程声明的上报步骤时离开设备，去向即流程声明的 https 目的地；运行期外发内容不持久化，失败摘要不保存外发数据值与凭据，其余数据边界条款不变
- **流程是数据不是代码的延续**：上报节点与负载模板仍是结构化数据与结构化引用，响应只作数据消费不执行——不引入任何代码执行面
- **可见即可控**：外发目的地、数据来源与凭据引用名在保存摘要外发级标注、清单常设标注；不启用零外发
- **凭据本机归属**：与定时计划同一模式——定义随流程同步、值留在本机
- **既有护栏零放宽**：上报副作用不比页面提交更宽松——同一运行锁、同一保守中止、同一不重试语义

## 4. 业务规则与状态

### 4.1 业务规则
- **外发边界**：数据离开设备仅两类目的地——同步服务器（既有 data-sync 语义）与本能力的流程声明上报端点；上报端点必须为流程文件内常量 https 网址，http 明文端点在交付校验整体拒绝；除负载模板引用的数据外，不附加任何未在流程中声明的数据（无遥测、无隐式字段）
- **外发可见性**：含上报步骤的流程在保存摘要中逐节点展示目的地、数据来源与凭据引用名（外发级标注，与提交类动作同级）；流程清单显示外发标注；本地交付与空间拉取同一展示标准；启用仅限用户本人，AI 不得代启（沿用基线启用管线）
- **凭据规则**：凭据为本机具名记录「名称 + 请求头名 + 值」（用户在扩展内录入、查看引用、删除），运行时以「请求头名: 值」单个请求头附载；头名与值都只在本机存储；流程文件只含引用名；凭据值不进流程定义、版本历史、摘要、失败提示与同步内容；运行时缺失或无效 → 保守中止并提示具体凭据名，零外发
- **执行语义**：上报请求作为带副作用步骤进入既有管线——单运行锁、业务实例占用（流程声明时）、防重复触发与来源标记照旧；请求方法限 GET/POST，负载模板为结构化引用；单次上报等待受硬上限约束并计入整次运行时长预算；非成功状态区间、网络不可达、等待超时、响应超限或凭据缺失 → 失败保守中止，不自动重试，已发生操作不回滚；预演（dry-run）执行到上报步骤时真实发送，与既有"预演提交即真实提交"语义完全一致（同一状态机、同一真实副作用、同一业务占用）
- **响应处理**：响应捕获为可选声明且大小受限；捕获内容进入流程数据槽位，供既有条件、断言与值引用词汇消费；扩展不执行、不注入、不存储返回内容中的任何逻辑（对应 CWS MV3 远程代码禁令）
- **失败可见性**：上报失败沿用会话内最近一次失败通道（节点、环节、简短原因：网络/状态/超时/凭据/响应超限），成功后清除；失败明细不保存外发负载值、响应内容与凭据
- **同步边界**：流程定义（含上报配置与凭据引用名）照常随空间同步；凭据值、运行期响应、上报结果记录一律不同步（"仅同步流程定义"边界不变，见 [`core/data-sync.md`](data-sync.md)）
- **格式版本**：上报节点为流程格式的词汇增量，schemaVersion 保持不变；携带非当前 schemaVersion 的文件整体拒绝并指引重新生成，不做迁移（沿用基线规则）；不含上报节点的既有流程零变化

### 4.2 关键状态与异常
- 运行终态沿用基线：成功（completed，含上报成功）；跳过（skipped：既有防重复语义）；失败（failed：触发/定位/动作/断言/等待/预算之外，新增上报环节——网络不可达、状态非成功区间、等待超时、响应超限、凭据缺失或无效，携带节点定位）；已取消（cancelled：既有取消面）
- 凭据记录状态：本机已录入（具名）⇄ 已删除；引用关系为流程内声明，无服务端状态
- 异常与兜底：
  - 目标服务器不可达或证书异常 → 上报步骤失败保守中止，不重试，提示简短原因
  - 服务器返回非成功状态 → 同上；不解析错误体、不据错误体继续
  - 响应超过大小上限 → 失败保守中止（捕获声明存在时），不截断续用
  - 引用凭据缺失或已删除 → 失败保守中止并提示凭据名，零外发
  - 上报后流程跨页续跑 → 占用与防重放语义照旧（跨页规则见 [`core/cross-page-flow.md`](cross-page-flow.md)）
  - 拉取端未录入对应凭据 → 该流程在拉取端可保存、可查看，运行至上报步骤时按凭据缺失失败并提示

## 5. 功能需求

### 5.1 核心需求
- **FR1 上报节点词汇与全量校验**：受约束步骤树新增上报请求节点（常量 https 目的地、GET/POST 封闭集、结构化引用负载模板、凭据引用名、期望成功状态区间、可选响应捕获声明与大小上限）；交付校验覆盖上述全部约束，违规整体拒绝并说明原因；流程格式文档与扩展校验器同步更新同一事实源
- **FR2 运行时执行与结果语义**：上报在既有运行管线内执行（单运行锁、业务实例占用、预算、跨页续跑沿用）；成功（2xx）继续，可选响应按声明捕获为数据；失败（网络/状态/超时/响应超限/凭据）保守中止、不自动重试、不回滚；预演与自动执行同一语义（预演上报即真实发送）；失败提示沿用会话内最近一次通道并含上报环节
- **FR3 本机具名凭据管理**：扩展内录入、查看与删除具名凭据（名称、请求头名、值三元组；仅本机存储、不同步、不进版本历史）；流程按引用名使用，运行时以单个请求头附载；运行时缺失或无效保守中止并提示凭据名；删除流程不强制删除凭据（凭据可被多流程引用，由用户自行管理）
- **FR4 外发可见性与披露**：保存摘要对上报步骤做外发级标注（目的地、数据来源、凭据引用名），本地交付与空间拉取同一标准；流程清单对含上报步骤的流程显示外发标注；启用仅限用户本人，保存即未启用
- **FR5 隐私政策与商店声明更新**：隐私政策与上报能力同步演进（出网目的地、凭据本机存储、外发数据不持久化、响应仅作数据）并更新 CWS 数据用途问卷、host 权限理由与商店页显著能力披露；材料更新完成是发布门槛

### 5.2 验收目标
以下为本能力的验收门槛（受控测试页 + 本地 https 接收端承载，不依赖外部服务）：

1. **上报闭环可走通**：含上报步骤的流程经本机通道交付、摘要外发级展示、用户启用后，在受控页运行完成"采集→上报→成功继续→响应捕获→后续断言"全程，接收端收到的负载与流程声明一致——全程无需开发者修改代码
2. **失败与保守语义正确**：非成功状态、网络不可达、等待超时、响应超限、凭据缺失五种场景均失败保守中止，失败提示含节点与环节，不自动重试，已发生页面操作不回滚；同一业务实例重复触发上报不重复（占用未解除即跳过）
3. **可见性与凭据边界**：摘要与清单外发标注在本地交付与空间拉取两端一致可见；凭据值不出现在摘要、失败提示、同步内容与版本历史；设备 B 拉取后无凭据值、零外发，录入本机凭据后可用
4. **校验与存量零回归**：http 目的地、封闭集外方法、非法负载引用、非法凭据引用名的流程在交付校验整体拒绝并说明原因；不含上报节点的既有流程行为不变；非当前 schemaVersion 文件整体拒绝行为不变
5. **披露材料同步**：隐私政策与商店声明材料与上报能力同时就绪（人工核对项，不做 e2e）

## 6. API 相关约束

**适用性**: 适用（能力边界与兼容性）

- **接口能力范围**：本能力不引入扩展自身运营的网络服务，不经 oncewise-ai-sync 或任何开发者服务代理、转发、存储上报内容；出网目的地为封闭两类——同步服务器（data-sync 语义不变）与用户流程声明的常量 https 上报端点；对外数据契约仍是"流程文件格式"（上报节点为格式词汇增量），与扩展校验器保持同一事实源
- **访问控制原则**：上报端点的认证凭据为本机具名记录，按名引用、仅本机；上报负载限于流程声明的结构化引用数据，无隐式附加数据；响应只作数据消费，不执行、不注入
- **兼容性原则**：manifest 权限零变更（使用既有 host 权限）；上报节点为流程格式词汇增量（schemaVersion 不变），不做旧文件迁移；基线 §6 网络表述为"扩展不运营网络服务；出网目的地限于同步服务器与用户流程声明的上报端点"

---

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：上报能力不新增页面——凭据管理入口位于侧边栏流程工作台（既有结构上扩展）；保存摘要与启用卡沿用导入页面
- **关键交互**：保存摘要中上报步骤外发级标注（目的地网址、数据来源、凭据引用名，与提交类动作同级显著）；流程清单外发标注常设；凭据录入（名称、请求头名、值）/查看引用名/删除在侧边栏完成，界面只显示引用名不回显值（录入时除外）
- **状态反馈**：上报失败沿用会话内最近一次失败行（节点、环节、简短原因），成功后清除；不提供上报历史与通用预演
- **数据可见性**：摘要、失败提示与同步内容不出现凭据值与外发负载值；界面语言 en 默认 + zh 完整翻译
- **兼容性**：无新增浏览器权限；验收基准环境为桌面 Chrome 与本地 https 受控接收端
