# 流程定时执行（support-scheduler） 产品需求文档 (PRD)

**创建时间**: 2026-10-17
**优先级**: P1
**发布时间**: 2026-11-25（补发布：能力已随 v1.3.0 于 2026-10-17 交付并完成 Demo 验收，2026-11-25 由草稿正式发布）

> 本 PRD 是基线 [`core/self-service-browser-automation.md`](self-service-browser-automation.md) 的触发模型扩展：基线「两类触发」（字段变化、进入页面）增加第三类「定时触发」，基线 §2.1/§3.2 的触发表述已随本 PRD 发布同步修订（见基线头部 2026-11-25 修订注）。
> 定时计划为设备本地记录，不随同步空间分发、不进入流程定义（DEC-support-scheduler-002），后端与同步协议零参与；到点自动前台开页与错过不补跑语义见 DEC-support-scheduler-001。运行安全全部沿用既有管线（单运行锁、业务实例占用、输入门禁、保守中止、执行预算、跨页续跑）。

## 1. 相关用户故事

### 1.1 相关故事
- `[US-SCH-001]` 管理流程的定时计划，优先级 P1，来源 `docs/user-stories/core/support-scheduler.md`
- 角色：AI 工具用户（定义见 `docs/user-stories/_roles.md`）

- `[US-SCH-002]` 到点自动执行，优先级 P1，来源同上
- 摘要：到点在已打开的匹配标签页执行，无匹配时扩展自动以前台标签页打开入口网址执行；未启用零动作；页面不符不启动并提示

- `[US-SCH-003]` 错过与到点门禁失败的可见性，优先级 P1，来源同上
- 摘要：浏览器未运行/唤醒过迟 → 错过提示且不补跑；输入未就绪 → 跳过并提示具体项目；提示沿用会话内生命周期

- `[US-SCH-004]` 定时与手动触发共用防重放，优先级 P1，来源同上
- 摘要：定时运行与手动触发共用运行互斥与业务实例占用，同一业务实例不重复提交；多计划同时到点独立串行；跨页流程照常续跑

- `[US-SCH-005]` 计划归属创建设备，优先级 P1，来源同上
- 摘要：计划为本机记录不同步，他设备拉取流程不带计划；删除流程清理本机计划；计划不进入流程定义

## 2. 范围界定

### 2.1 包含功能
- **定时计划管理**：为已启用流程创建/编辑/删除计划；周期表达为封闭集——本机时区的每日/每周墙钟时刻（含夏令时切换日按墙钟对齐）与固定间隔；计划创建时保存入口网址；计划列表展示下一次触发时刻；设备上计划数量有上限保护，达上限时创建被拒绝并提示
- **到点自动执行**：到点先寻找已打开的匹配标签页并在其中执行；无匹配时由扩展自动以前台标签页打开计划保存的入口网址并执行（DEC-support-scheduler-001）；打开或选中的页面仍须通过流程的页面特征门禁才启动；运行沿用既有管线——输入快照门禁、单运行锁、业务实例占用、保守中止、执行预算、同站顺序跨页续跑
- **错过与门禁失败可见**：浏览器未运行、或唤醒/处理过迟超出有界宽限范围 → 该次按错过处理：跳过并记录会话内失败提示，不补跑、不自动重试（DEC-support-scheduler-001）；浏览器重启后的遗留已过期待触发同样落错过提示
- **计划本机归属与清理**：计划为设备本地记录，不随同步空间分发、不进入流程定义；流程删除时其计划随之清理；流程本体（含输入项定义）照常同步
- **计划管理 UI**：侧边栏流程工作台内的计划管理界面，en 默认 + zh 完整翻译（DEC-self-service-browser-automation-017）

### 2.2 不包含功能 (Out of Scope)
- 错过补跑与自动重试——错过只提示不执行（DEC-support-scheduler-001）
- 隐藏/后台标签页执行——定时开页以前台为默认；执行中用户切走引发的节流/预算失败按既有保守中止处理，不为此引入隐藏标签页执行路径（DEC-support-scheduler-001 重开条件未触发）
- 计划随同步空间分发、计划进入流程定义、跨设备计划协调或去重（DEC-support-scheduler-002）
- 服务端调度——后端（oncewise-ai-sync）零参与，无服务端定时、通知或推送能力
- cron 表达式、自然语言时间解析——周期表达限于 §2.1 封闭集，不引入时间解析引擎
- 跨标签页流程调度——维持基线排除条款：一次定时触发 = 单标签页内一次运行（可声明同站顺序跨页）；不存在同时或交替操作多个标签页的定时运行
- 持久定时执行历史/运行日志——错过与失败提示沿用会话内生命周期，成功后清除，浏览器重启后不再可见
- 系统级通知渠道（系统通知、邮件等）——提示限于侧边栏会话内失败通道
- 代理启用——计划只作用于已启用流程，不引入任何由计划代为启用/授权的路径（DEC-self-service-browser-automation-015）
- 新增第三方依赖——唯一新增平台权限为浏览器定时唤醒能力（`alarms`），无新库

### 2.3 依赖项
- 已启用的流程（启用仅限用户本人操作，DEC-self-service-browser-automation-015/016）；声明输入项的流程需本机已保存有效输入值（输入能力见 [`core/form-support.md`](form-support.md)）
- 既有触发、防重放、失败提示与跨页续跑管线（基线及 cross-page-flow PRD）——定时是新增触发入口，不另建运行机制
- 浏览器处于运行状态——扩展无法在浏览器关闭时工作；关闭期间到点按错过处理
- 浏览器定时唤醒平台能力（manifest 新增 `alarms` 权限）

## 3. 需求概述

### 3.1 功能描述
用户把验证过的操作固化为可开关流程后，到点仍需亲自打开目标页面才能触发执行。本能力允许用户为已启用流程建立定时计划：计划时刻到达时自动执行——已有匹配标签页就在其中执行，没有则由扩展自动以前台标签页打开计划保存的入口网址执行，无需人工在场。执行安全与结果可见全部沿用既有管线：同一业务实例不会被重复提交，失败与错过在侧边栏可见，任何失败保守中止不重试。计划归属创建它的设备，不随流程同步；因此每台设备按自己的计划独立触发——同一计划只在其创建设备上到点，不会被复制到其他设备，各设备上自建的计划之间不协调、不去重（见 §2.2）。本能力强化「日常执行」环节，属既有闭环内的能力扩展，不改变内部试验定位（DEC-self-service-browser-automation-008）。

### 3.2 关键特性
- **第三类触发，运行模型不变**：定时成为字段变化、进入页面之外的第三类触发；触发模型扩展，运行期（单运行锁、业务占用、保守中止、预算）零改动沿用
- **无人值守但有页面供给**：到点无匹配页面时自动以前台打开入口页，保证运行有所需的页面环境；页面特征门禁仍是启动前提，页面不符零动作
- **错过显式化，语义与平台解耦**：唤醒过迟/浏览器未运行的触发按有界宽限范围判定为错过，跳过并提示、不补跑；不依赖浏览器对错过唤醒的补发行为
- **计划设备本地**：计划不进入流程定义、不经同步空间分发；流程本体照常同步，他设备拉取后自行决定是否建计划
- **既有护栏零放宽**：定时运行与手动触发共用全部防重放与保守中止语义；错过的危险方向受保护（只会少做，不会多做）

## 4. 业务规则与状态

### 4.1 业务规则
- **计划作用面**：计划只作用于已启用流程；到点重新校验启用状态与流程指纹（与既有自动触发同一门禁）。到点时流程未启用（暂停/关闭）→ 本次零动作、不记失败，计划保留，恢复启用后按后续时刻触发；不引入任何代理启用路径
- **运行授权沿用**：定时触发的流程可含提交类动作，沿用启用后自动执行、无逐次确认（DEC-self-service-browser-automation-010）；调度为扩展侧执行能力，无 AI/模型参与（DEC-self-service-browser-automation-009）
- **周期表达**：封闭集——每日/每周墙钟时刻（按本机时区，夏令时切换日仍对齐墙钟时刻）、固定间隔；编辑计划即重排下一次触发时刻，不保留历史安排
- **到点页面供给次序**：先按流程站点寻找已打开的匹配标签页；无匹配 → 以前台标签页打开计划保存的入口网址；打开或选中的页面须通过流程声明的页面特征门禁才启动，不符则保守不启动并落会话内失败提示
- **错过判定**：预定触发时刻与实际处理时刻的偏差超出有界宽限范围 → 错过；浏览器关闭期间到点的计划在下次启动时检测遗留已过期项并同样落错过提示。错过 = 跳过该次 + 会话内失败提示，不补跑、不自动重试，随后按计划排下一次
- **提示生命周期**：错过、页面门禁拒绝、输入门禁拒绝与运行失败共用既有会话内失败提示通道——成功后清除、浏览器重启后不再可见；不新建持久执行历史
- **输入供给**：声明输入项的流程以「本机已保存且有效」的输入值为定时运行的输入；必填缺失或值无效 → 该次跳过、零页面动作并提示具体项目（沿用 form-support 语义；无人在场无法补填）
- **触发与防重放**：一次定时触发 = 单标签页内一次运行；同次到点至多启动一次；定时运行与手动触发共用单运行锁与 `站点+流程+业务实例` 业务实例占用——占用未解除或已处理则跳过并说明原因，失败或结果未知不自动解除；多个计划同时到点为各自独立的单运行，同业务实例按占用串行，不触碰「跨标签页流程调度」排除条款
- **跨页续跑**：定时触发的流程可声明同站顺序跨页，续跑、防重放与失败可见语义与手动触发一致
- **运行期页面处置**：定时打开的标签页以前台为默认；执行中用户切走导致的节流/预算失败按既有保守中止处理；运行结束标签页保留（页面即结果证据，页面静默沿用）
- **计划生命周期与归属**：创建/编辑（重排下一次触发）/删除即时生效；删除流程时其计划随之清理；计划为设备本地记录，不进入流程定义、不影响流程版本比较、不经同步空间传输

### 4.2 关键状态与异常
- 计划状态：活跃（等待下一次触发）⇄ 已删除；计划无独立暂停态——暂停/关闭流程即停止其全部计划的触发，计划保留
- 定时触发的运行终态沿用基线：成功（completed）；跳过（skipped：占用未解除、已处理、输入缺失或无效，附原因）；失败（failed：页面门禁拒绝、定位/动作/断言/等待/预算，携带节点定位）；已取消（cancelled：既有取消面，含执行中关闭标签页）
- 「错过」为触发层结果（未形成运行）：跳过该次 + 会话内提示，按计划排下一次；与运行终态「跳过」分开呈现原因
- 异常与兜底：
  - 到点页面与流程声明不符（站点改版、登录态过期、入口网址失效）→ 保守不启动 + 会话内失败提示；入口网址可在计划管理中维护
  - 计划数量达上限 → 创建被拒绝并提示，既有计划不受影响
  - 浏览器关闭期间多次到点 → 各次均按错过处理，不补跑、不合并为一次执行；同一流程的多次错过合并为一条提示，显示次数与最近一次时刻；同轮该流程另有已过期的定时触发时，只保留该过期提示
  - 多标签页/多计划对同一业务实例竞争 → 只有一个执行者，其余跳过并说明原因

## 5. 功能需求

### 5.1 核心需求
- **FR1 定时计划管理**：在侧栏流程工作台为已启用流程创建、编辑、删除计划；周期限于封闭集（每日/每周墙钟时刻、固定间隔）；计划保存入口网址并展示下一次触发时刻；编辑即时重排、删除即时生效；设备计划数量达上限时创建被拒绝并提示
- **FR2 到点自动执行**：计划时刻到达，先在已打开的匹配标签页执行，无匹配时自动以前台标签页打开计划保存的入口网址执行（DEC-support-scheduler-001）；页面须通过流程页面特征门禁；进入与手动触发完全相同的运行管线；同次到点至多启动一次
- **FR3 输入门禁沿用**：声明输入项的流程到点读取本机已保存且有效的输入值；必填缺失或值无效则跳过、零页面动作，并提示具体缺失或无效项目
- **FR4 错过处理**：唤醒/处理过迟超出有界宽限范围、或浏览器关闭期间到点 → 该次按错过处理：跳过 + 会话内失败提示，不补跑、不自动重试，随后按计划排下一次；浏览器重启后检测遗留已过期待触发并同样落错过提示（DEC-support-scheduler-001）
- **FR5 防重放与互斥沿用**：单运行锁与业务实例占用覆盖定时与手动触发并发、多计划同时到点；占用未解除或已处理则跳过并说明原因；失败或结果未知不自动解除占用；跨页运行的占用跨页保持
- **FR6 计划本机归属与清理**：计划为设备本地记录，不随同步空间分发、不进入流程定义、不影响流程版本；他设备拉取流程不带计划；删除流程时其计划随之清理（DEC-support-scheduler-002）
- **FR7 失败与错过可见性沿用**：错过、页面/输入门禁拒绝、运行失败均落既有会话内失败提示（流程清单与详情可见最近一次，含原因）；成功后清除；不提供定时执行历史与通用预演入口

### 5.2 验收目标
以下为本能力的验收门槛（受控测试页承载，e2e 以可控短间隔/伪造到点时刻推进时间，不等待真实墙钟）：

1. **定时闭环可走通**：为已启用流程创建每日计划，到点无匹配标签页 → 前台自动打开入口页并完成执行，页面结果可核对，运行结束标签页保留；已有匹配标签页时在该页执行——全程无需开发者修改代码
2. **错过语义正确**：浏览器关闭期间到点 → 重启后可见错过提示且该次不补跑，下一次按计划触发；唤醒过迟超出宽限范围 → 记错过并按计划排下一次
3. **不可重复提交**：同一业务实例在定时+手动并发与多计划同时到点时，提交类动作实际执行次数为 1 或 0（跳过）；占用未解除的定时触发被跳过并说明原因
4. **门禁与输入边界**：必填缺失或输入值无效 → 零页面动作 + 提示具体项目；到点页面特征不符 → 不启动 + 提示；流程暂停/关闭 → 零动作；定时触发的跨页流程按页序续跑完成
5. **本机归属与存量零回归**：设备 B 拉取同流程后无计划、不触发、清单不显示设备 A 的计划；不含计划的既有流程（含提交类流程）行为不变；删除流程后其计划不再触发

## 6. API 相关约束

**适用性**: 不适用

本 feature 不引入网络服务与对外 API，后端与同步协议零参与。对外唯一数据契约仍是「流程文件格式」且不变——计划不进入流程定义，不引入格式版本变更；同步的「仅同步流程定义、不同步运行数据与计划」边界不变（见 [`core/data-sync.md`](data-sync.md)）。

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：计划管理位于侧边栏流程工作台内（流程详情/工作台既有结构上扩展），不新增页面或导航；不限定特定站点页面
- **关键交互**：创建/编辑计划（周期封闭集 + 入口网址）→ 保存后展示下一次触发时刻 → 编辑即时重排、删除即时生效；计划数量达上限时给出明确拒绝提示
- **状态反馈**：错过、页面/输入门禁拒绝与运行失败沿用流程清单与详情的最近失败行（含简短原因），成功后清除；定时开页执行保持页面静默（无提示弹层）
- **可见性**：计划与入口网址仅本机可见，不同步给空间参与者；界面语言 en 默认 + zh 完整翻译（DEC-self-service-browser-automation-017）
- **兼容性**：新增浏览器 `alarms` 权限（本 feature 唯一新增权限）；验收基准环境为桌面 Chrome；定时开页以前台为默认，隐藏标签页节流后果按保守失败处理并可见
