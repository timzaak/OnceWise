## 2. 范围界定

### 2.1 包含功能
- **多页流程表达**：流程声明入口页（触发绑定面，语义不变）与有序的后续声明页（每页有特征指纹）；步骤树中可声明"本次跳转后将到达某声明页并继续"；跳转本身只能由既有白名单点击动作（提交按钮、翻页链接，含新标签页打开）触发，流程不引入新的页面跳转能力
- **跨页运行连续性**：同一次运行跨页面继续直到终态；前序页面读取的数据、循环进度与执行预算跨页延续；页面间等待有截止时间，超时按失败停止
- **意外中断保守取消**：手动刷新运行中的页面、关闭运行所在标签页、浏览器崩溃/重启、流程暂停/删除/换版时取消本次运行，不自动从断点恢复，不保存可恢复的运行快照（DEC-cross-page-flow-002）
- **防重放跨页延续**：业务实例占用跨页面保持——同一张单据（同站点同流程同业务标识）整条跨页流程只执行一次，中断后的再次进入不重放；恢复继续时复核业务标识，落到另一单据的声明页即取消
- **失败可见性带页定位**：实际触发失败后，侧边栏显示失败发生在哪一页、哪一步（节点与循环位置沿用），成功后清除
- **交接与同步兼容**：多页流程经既有 AI 本机通道校验、保存与启用（同一校验路径、摘要含声明页清单）；流程同步发布/拉取/版本比较自动感知多页内容，同步协议不变
- **受控验收载体**：提供多页向导受控测试页（含新标签页变体与受控延迟/失败信号），承载跨页执行、防重放与中断场景的验收

### 2.2 不包含功能 (Out of Scope)
- 跨站点串联（流程仍限定单一站点域名，后续页与入口页同站点）（DEC-cross-page-flow-001）
- 跨标签页编排（不存在同时或交替操作多个标签页的流程步骤；新标签页打开的声明页只是顺序继续）与并行节点（维持 DEC-self-service-browser-automation-019 排除）
- 页面内路由变化导航（不换页面的站内视图切换仍由现行同页面步骤树覆盖，跨页声明只表达整页跳转）
- 意外中断后的自动续跑或运行快照恢复（DEC-cross-page-flow-002）
- 扩展主动发起页面跳转的原语（导航只能由既有白名单动作触发）
- 新增浏览器权限、新增外部依赖
- 旧格式迁移（沿用基线"非当前格式整体拒绝、不做迁移"条款；本轮为当前格式的可选能力增量，不引入版本号变更）

### 2.3 依赖项
- 用户自有 AI 工具与流程交接通道（Agent Skill + 本机通道，见 [`core/support-native-messaging.md`](support-native-messaging.md)）——多页流程的产出、校验与保存沿用该通道
- 既有触发与防重放模型（入口页两类触发、业务实例占用）——跨页能力在其上扩展，不另建机制
- 受控测试页本地环境（本地静态页面，无外部服务依赖）

## 3. 需求概述

### 3.1 功能描述
已经使用 AI 工具的用户，在向导式多页业务（如订单填写→确认→结果）中，此前只能把每页操作拆成独立流程手工衔接，且流程间无法传递数据、无法保证整段业务只提交一次。本能力允许 AI 把同一站点多个页面的连续操作产出为一条跨页流程：每页特征显式声明，跳转由流程内已有的点击动作触发，运行在页面间连续完成。启用后日常进入入口页即自动执行整段；中途任何失败、超时或意外中断都保守停止，已完成操作保留在页面上由用户接手，同一业务实例不会被重复提交。

### 3.2 关键特性
- **流程仍是数据不是代码**：多页表达是既有受约束步骤树的可选扩展（声明页清单与跳转声明），不引入代码、表达式或新的副作用通道
- **预期跳转续跑、意外中断取消**：只有流程声明的跳转（声明页特征 + 跳出页面关系 + 截止时间内）才继续运行；手动刷新、改址、关标签页、重启即取消
- **整段业务一次提交**：业务实例占用贯穿全部页面；继续执行时复核业务标识，防止串单
- **失败可定位到页**：失败明细携带页信息，与既有节点/循环定位叠加
- **存量流程零影响**：不含多页声明的既有流程行为不变

## 4. 业务规则与状态

### 4.1 业务规则
- **声明式页序**：入口页指纹仍是唯一触发绑定面（进入页面/字段变化触发都在入口页评估）；后续页由流程按序声明，每页特征指纹沿用现行判定规则（URL 特征 + 可选内容特征，歧义视为不命中）；每个声明的后续页必须被流程内的跳转声明引用，否则整条流程在交付校验时拒绝
- **跳转语义**：跳转声明紧跟触发跳转的既有白名单点击动作之后，只声明"将到达某声明页并在此页继续"，不产生跳转本身；页面间等待受既有等待预算约束，流程只能取更小值
- **数据延续**：前序页面读取的数据与循环进度在后续页面可用；跨页身份一致性由流程内读取与断言表达（沿用既有步骤词汇）
- **防重放单位不变**：站点 + 流程 + 业务实例的占用在整段跨页运行期间保持，失败或结果未知不解除；继续执行时复核业务标识——值不同或歧义即取消，目标字段不在该页时跳过复核（由流程内断言承担页内身份）
- **保守中止**：任一页面上的元素缺失、定位歧义、校验/断言失败、等待超时、跳转后声明页未按时到达或预算超限，立即停止整段运行；已发生在各页上的操作不回滚、不重试，页面留给用户接手
- **取消面**：暂停/删除/换版流程、离开运行所在标签页（关闭或跳去非声明页）、手动刷新运行中的页面、浏览器崩溃/重启，均取消本次运行及未开始的后续页面；取消只阻止后续行为，不撤回已发出的提交
- **数据边界**：跨页运行期间暂存的运行数据仅存在于本机浏览器会话存储，窗口结束（继续完成/超时/取消）即清除；不进入日志、证据、同步与任何导出（沿用"运行期读取的页面数据只在本机出现"边界）
- **中间页不当新触发**：后续页面到达只作为继续条件，不把同一流程当作新入口执行；与入口指纹重叠的病态声明由防重复机制压制
- **多流程边界**：沿用基线"单流程场景为验收范围"；多条流程在同页并存的执行顺序不纳入本轮验收

### 4.2 关键状态与异常
- 流程状态机不变：未启用（导入默认）→ 已启用 ⇄ 已暂停（暂停取消当前运行，含跨页在途运行）
- 运行终态不变：成功（completed，最后一页完成）；跳过（skipped：占用未解除、已处理或防重复判定，附原因）；失败（failed：含跳转后声明页未到达、业务标识复核不同/歧义，携带页与节点定位）；已取消（cancelled：意外中断、暂停/删除/换版、离开运行标签页）
- 跳转后等待下一页的窗口是运行的中间状态，不单独向用户报告；窗口结束时按继续/失败/取消进入对应终态
- 异常与兜底：
  - 多页流程文件不符合格式（声明页未被引用、跳转声明引用不存在的页、等待超预算）→ 交付整体拒绝并说明原因，已有流程不受影响
  - 旧版本扩展收到多页流程 → 整体拒绝并说明不支持的步骤，不静默当作单页流程执行
  - 跳转后到达了内容相似但特征不匹配的页面 → 视为未到达，按截止时间失败停止
  - 两个标签页同时到达声明页 → 只有一个继续运行，另一侧无自动动作

## 5. 功能需求

### 5.1 核心需求
- **FR1 多页流程交付与摘要**：多页流程经既有 AI 本机通道校验并保存为未启用；可读摘要覆盖入口页与全部声明页、跳转声明与提交类动作标注（沿用既有摘要与确认语义，无新增门禁）；含多页声明的流程文件与单页流程走完全相同的启用与授权路径
- **FR2 跨页自动执行**：触发后在入口页开始执行；流程声明的跳转发生后，运行在到达的声明页继续（含新标签页打开的声明页，原标签页不再动作），直到最后一页完成；同一次触发整段只执行一遍
- **FR3 页间等待与超时**：跳转后等待声明页到达有截止时间（受既有等待预算约束），超时按失败保守停止、不重试跳转；跳转没有实际发生（如站点拦截提交停留在原页）同样按超时失败处理
- **FR4 意外中断保守取消**：手动刷新运行中的页面、关闭运行所在标签页、重启浏览器、暂停/删除/换版流程时取消整段运行；取消后再次进入不自动从断点恢复；已完成操作保留在页面上
- **FR5 防重放跨页延续**：业务实例占用贯穿跨页运行；中断或失败后同一业务实例的再次进入被跳过并说明原因；继续执行时复核业务标识，不同或歧义即取消
- **FR6 失败可见性带页定位**：实际触发失败后，侧边栏与流程详情显示最近一次失败的页、节点、循环位置、环节与简短原因；成功后清除；不提供执行历史
- **FR7 存量流程零影响**：不含多页声明的既有流程的校验、启用、执行、同步与失败可见行为全部不变；多页能力为可选声明，不引入格式版本变更

### 5.2 验收目标
以下为本轮验收门槛（受控测试页承载，真实站点验证沿用基线证据边界）：

1. **多页闭环可走通**：三页向导（填写→确认→结果）作为一条流程经本机通道交付、用户核对摘要后启用；进入入口页后三页顺序自动完成，每页动作与结果可核对，同一张单据最终提交恰好一次——全程无需开发者修改代码
2. **新标签页变体正确**：确认页以新标签页打开结果页时，运行在新标签页继续并在其上完成；原标签页不再产生自动动作
3. **超时与中断保守**：跳转后声明页在截止时间内未到达（含点击后停留原页）→ 失败停止且不重试，失败位置含页信息；运行中手动刷新/关标签页/暂停流程 → 取消且同一单据不被重复提交
4. **防重放跨页有效**：已执行过提交的单据，刷新入口页或重复进入任一声明页 → 跳过并说明原因、零自动动作；两个标签页同时到达声明页 → 只有一个继续
5. **存量零回归**：不含多页声明的既有流程（含提交类流程）在升级后行为不变；旧版本扩展对多页流程整体拒绝且给出可读原因

## 6. API 相关约束

**适用性**: 适用（能力边界与兼容性）

- **接口能力范围**：本能力不引入网络服务与对外 API（沿用基线 §6）；对外唯一数据契约仍是"流程文件格式"——多页声明（后续页清单与跳转声明）是该格式的可选能力增量，由外部 AI 工具按格式文档产出、由扩展端校验器全量校验；格式文档与校验器保持同一事实源
- **访问控制原则**：无服务端数据边界变化；跨页运行期间的暂存数据仅在本机浏览器会话存储、窗口结束即清除，不同步、不导出
- **兼容性原则**：不引入格式版本号变更——不含多页声明的既有流程在新版本下原样合法、零迁移；旧版本扩展收到含多页声明的流程时整体拒绝并说明原因，不静默按单页执行；流程同步（发布/拉取/版本比较）自动感知多页内容，同步协议与"仅同步流程定义、不同步运行数据"的边界不变（见 [`core/data-sync.md`](data-sync.md)）

---

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口不变**：侧边栏工作台与导入/管理页面职责沿用基线 §7，不新增页面或导航
- **摘要与详情**：导入核对摘要、保存后摘要与流程详情展示入口页与声明页清单、跳转声明步骤；提交类动作显著标注与敏感值脱敏沿用
- **失败反馈**：流程清单与详情的最近失败行增加页定位（如"于页 确认页"），与既有节点/循环位置叠加；跳过与取消不产生页面打扰（页面静默沿用）
- **状态反馈**：多页流程的启用、跳过原因、失败原因文案遵循既有 i18n 双语规范
- **兼容性**：浏览器与权限要求不变（不新增任何浏览器权限）
