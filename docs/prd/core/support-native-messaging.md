## 2. 范围界定

### 2.1 包含功能

- **本机流程交接通道**：Skill 交接包随附本机程序；AI 在目标网页验证通过后，经该程序与用户 Chrome 中已安装扩展的 Native Messaging 连接交付流程（新建与修订）。扩展仍是流程校验与持久化的唯一执行方。
- **受限的本机入口**：扩展侧本机消息入口只接受流程读取、校验、保存与替换四类操作；不提供启用、删除、任意脚本执行或浏览器操作。
- **三平台安装与连通**：Windows、macOS、Linux 的用户级安装、与实际扩展实例的绑定、连通验证与卸载；未就绪时交付明确失败并给出修复指引。
- **对话确认与保存后展示**：AI 先向用户说明本次流程内容及验证范围，取得明确确认后经本机通道保存；扩展呈现保存结果、可读摘要与用户本人可操作的一键「启用」确认。
- **修订交接**：从流程详情「用 AI 优化」发起时先暂停原流程；AI 经本机通道读取现有定义并交付修订，按原流程 ID 覆盖、冲突拒绝、落为未启用。
- **本地版本历史与回滚**：扩展为每条流程保留最近 10 个成功保存版本；用户在流程详情查看并选择旧版本回滚，回滚后流程保持未启用。
- **Skill 与文档更新**：oncewise-setup 提供安装与连通指引，oncewise-flow 的交接步骤走本机通道；安装与使用说明同步维护。

### 2.2 不包含功能 (Out of Scope)

- 经本机通道读取或操作目标网页——目标网页的探索、定位与现场验证仍只使用 Chrome DevTools MCP（DEC-support-native-messaging-001）。
- 经本机通道启用或删除流程的能力；启用只能由用户在扩展界面操作（承接既有决策）。
- 把本机通道做成扩展侧 MCP 服务或通用命令行入口——DEC-self-service-browser-automation-013 的其余条款（Skill 交接包形态）继续适用。
- AI 操作导入页作为并行导入通道（Q-support-native-messaging-001：替换而非并行）；亦不提供面向用户的手动导入（文件/粘贴）通道。
- 修改 Rust 同步服务或脚本版本同步边界；经本机程序绕过扩展直接读写流程存储。
- Firefox 等非 Chrome 浏览器与移动平台。
- 同一本机多浏览器实例并存时的通道管理产品能力——安装时绑定用户所选浏览器实例，不做多实例切换或并存设计。
- 流程格式、运行期语义、触发条件、防重复护栏等既有能力的变更。
- AI 经本机通道代用户回滚；把版本历史同步到团队空间，或保存流程执行历史。

### 2.3 依赖项

- 用户桌面 Chrome（114 及以上基线）与已安装的 OnceWise 扩展。
- Skill 指引指定版本的 Node.js 运行时（本机程序依赖；具体版本锁定属技术设计）。
- Chrome DevTools MCP（目标网页探索与现场验证，用户自行安装配置）。
- Skill 交接包（oncewise-setup / oncewise-flow）随仓库分发。

## 3. 需求概述

### 3.1 功能描述

已经使用 AI 工具的用户在自有工具中描述网页流程，AI 借 Chrome DevTools MCP 在浏览器中探索并验证操作；验证通过后，AI 按流程格式产出结构化流程，经 Skill 随附的本机程序把流程候选交给扩展校验（不经扩展导入页操作）。AI 向用户说明本次内容、验证范围及扩展给出的摘要，取得对本次内容的明确确认后经本机通道保存；扩展保存为未启用并呈现结果，启用仍由用户本人操作。修订已有流程走同一通道：用户从流程详情发起优化并暂停原流程，本机宿主向 AI 提供原流程完整内容，AI 在目标页复验并取得确认后按原 ID 覆盖。每条流程最近 10 个成功保存版本保留在本机，用户可从流程详情选择旧版本回滚。

本功能的目的（DEC-support-native-messaging-001、007～010）是消除 AI 逐控件操作导入页的交接摩擦，让“验证 → 对话确认 → 交付保存 → 核对 → 启用”闭环在三平台桌面环境稳定可走通，并让用户在流程修订后能从本地历史恢复旧版本。

### 3.2 关键特性

- **交接即接口**：AI 经本机程序交付流程，浏览器导入页不是 AI 的操作对象；扩展负责校验、保存结果、摘要与启用展示。
- **扩展是唯一校验与持久化方**：本机程序只中继受限请求，一切校验、写入与站点脚本重对齐都在扩展既有路径内完成。
- **入口能力白名单**：本机入口仅允许在用户发起优化时读取指定原流程，以及校验、保存或替换流程；不提供启用、删除、回滚或浏览器操作能力。
- **结果真实**：候选已接收、校验拒绝、连接失败及保存成功分别反馈；请求发出但结果未返回时标记结果未知，先核对扩展状态，不重复盲写。
- **启用仍归用户**：保存默认未启用；一键启用卡仅由用户本人操作（承接 DEC-self-service-browser-automation-016）。
- **本地历史可恢复**：每条流程只保留最近 10 个成功保存版本；用户在扩展内选择旧版本回滚，回滚后保持未启用。
- **三平台一致**：Windows、macOS、Linux 的安装、连通与交付遵循同一产品语义，差异只体现在安装形态。

## 4. 业务流程与状态

### 4.1 业务流程

1. **通道唯一**：AI 交付流程的唯一通道是本机通道；AI 操作导入页填写/保存不是产品通道，不为其设计、引导或验收。面向用户的手动导入（文件/粘贴）通道继续不提供（DEC-support-native-messaging-001 取代 DEC-self-service-browser-automation-015 的导入通道部分，其余条款继续有效）。
2. **扩展是唯一校验与持久化方**：本机程序不得在本地改写流程或绕过扩展写流程存储；所有交付经扩展现有全量校验（结构、控制流语义与预算）与写入路径处理，携带未知 schemaVersion 的文件整体拒绝并指引按当前格式重新生成。
3. **入口白名单**：本机入口只提供流程读取、校验、保存、替换；启用、删除、回滚、任意脚本执行、浏览器操作不提供，越界请求被拒绝且不产生副作用。
4. **保存前确认在对话内**：AI 须就本次流程内容（新建或修订）取得用户的明确确认后才经本机通道发起保存；扩展不在本机入口增设保存确认门禁，也不得表述为存在该门禁（DEC-support-native-messaging-007）。最初提出创建需求不等于确认保存。
5. **保存默认未启用、启用仅用户**：经本机通道保存的流程处于未启用状态，不执行任何页面动作；本机通道不提供启用操作。
6. **修订冲突保护**：修订以原流程 ID 覆盖且落为未启用；原流程在修订期间被修改、重新启用或删除时拒绝覆盖并保留当前内容；放弃修订时原流程保持暂停。
7. **安装与实例绑定**：本机程序按用户所选浏览器与操作系统做用户级安装并绑定实际扩展实例；未安装、绑定失效或扩展未运行时，交付明确失败并指引修复，不静默降级到其他通道。
8. **结果真实回报**：未就绪或扩展明确拒绝时返回失败；保存请求发出后断线或超时但未收到扩展结果时，标记结果未知，先读回扩展状态再决定是否重试，不宣称成功或零写入；成功报告与扩展读回状态一致。
9. **本机安全边界**：本机通道仅在本机当前用户作用域内开放，不经网络，不向页面脚本暴露；流程内容与交接记录不写入不必要的持久文件。
10. **目标页能力边界**：目标网页的读取与操作不经本机通道；探索与现场验证继续由 AI 经 Chrome DevTools MCP 完成（DEC-support-native-messaging-001）。
11. **本地历史与回滚**：扩展为每条流程保留最近 10 个成功保存版本（含当前版本），超出后移除最旧版本；历史只保存在本机，不进入同步空间。用户在流程详情选择旧版本并确认回滚；回滚形成新的当前版本、保留可回滚的先前内容，仍受 10 版本上限约束。回滚后流程为未启用，只有用户本人重新启用才执行。回滚失败不部分改写当前流程或历史；删除流程时一并删除其本地版本历史。

既有业务流程中不受交接通道影响的部分——流程是数据不是代码、用户自选站点、注入与流程站点绑定、能力白名单与提交类语义、防重复护栏、保守中止、运行取消与预算、数据脱敏、排除平台声明——继续按已发布 PRD 适用。

### 4.2 关键状态与异常

| 状态或情形 | 用户可见结果 | 流程与执行结果 |
|---|---|---|
| 交接环境就绪 | 连通验证通过，报告所绑定浏览器与扩展 | 可经本机通道交付 |
| 交接环境未就绪（未安装、文件移动、绑定失效、扩展未运行） | 交付失败并给出修复指引 | 不发生任何保存；扩展状态不变 |
| 交付校验通过 + 用户确认 | 摘要展示 + 保存成功反馈 | 新建/覆盖为未启用流程；站点脚本同步重对齐 |
| 交付校验通过 + 用户未确认或要求修改 | 无保存反馈 | 不保存；修改后重新校验与确认 |
| 交付校验失败（格式、不支持节点、非法引用、越界预算、未知 schemaVersion） | 拒绝原因（含具体条目） | 零写入，已有流程不受影响 |
| 越界请求（启用、删除、回滚、脚本执行、浏览器操作） | 拒绝反馈 | 拒绝执行，无副作用 |
| 保存请求尚未送达时断线 | 明确交接失败与可能原因 | 扩展状态不变 |
| 保存请求发出后断线或超时 | 明确标记结果未知，指引核对扩展状态 | 不自动重试，不推断写入结果 |
| 修订冲突（原流程已变化/启用/删除） | 拒绝原因 | 当前流程内容保留；可重新发起优化 |
| 用户从本地历史回滚 | 显示所选版本与回滚结果 | 恢复为新的当前版本，状态为未启用；保留最近 10 个版本 |
| 回滚失败 | 显示失败原因 | 当前内容与可用历史不发生部分改写 |
| 流程状态 | 与现状一致 | 未启用 → 已启用 ⇄ 已暂停 |

## 5. 功能需求

### 5.1 核心需求

- **FR1 本机交接环境安装**：oncewise-setup 指引 AI 在 Windows、macOS、Linux 完成用户级安装、绑定实际扩展实例并做连通验证，验证结果真实报告；支持卸载且卸载不影响扩展其余功能。
- **FR2 新流程交付**：AI 经本机通道交付流程候选；扩展执行全量校验（结构、控制流语义与预算）并给出可读摘要（提交类动作显著标注）；AI 在对话中取得用户对本次内容的明确确认后发起保存，扩展保存为未启用并展示结果；校验失败（含未知 schemaVersion）整体拒绝、零写入。
- **FR3 修订交付**：从流程详情「用 AI 优化」发起时先暂停原流程；AI 经本机通道读取现有定义、在目标页复验受影响步骤并交付修订；经同一校验和对话确认后，AI 发起按原流程 ID 覆盖，结果为未启用；修订期间原流程被修改、重新启用或删除时拒绝覆盖。
- **FR4 受限入口与真实结果**：本机入口仅提供流程读取、校验、保存、替换；越界请求拒绝且无副作用；未就绪或明确拒绝返回失败，保存请求发出后断线或超时标记结果未知并核对扩展状态；成功结果与扩展真实状态一致。
- **FR5 保存后展示与启用**：保存成功后扩展呈现摘要与一键「启用」确认，由用户本人操作（承接 DEC-self-service-browser-automation-016）；导入页仅承担保存后摘要与启用展示，不承担 AI 填写/校验/保存职责；侧边栏保持流程管理工作台定位不变。
- **FR6 Skill 与说明**：oncewise-setup / oncewise-flow 的流程指引与安装、使用说明以本机通道为准；相关文档与 Skill 指引不引导 AI 操作扩展导入页。
- **FR7 本地历史与回滚**：扩展为每条流程保留最近 10 个成功保存版本；流程详情提供版本查看与用户确认回滚，回滚后当前流程为未启用。历史不经本机入口提供回滚操作，不进入同步空间。

### 5.2 验收目标

1. **三平台闭环可走通**：在 Windows、macOS、Linux 的真实 Chrome 环境中各完成一次「安装与连通验证 → 受控页 AI 验证 → 新流程交付（校验通过、对话确认、AI 经本机通道保存为未启用）→ 扩展展示摘要 → 用户一键启用 → 自动执行 → 修订交付与冲突拒绝」的完整闭环，全程无需 AI 操作扩展导入页或开发者修改代码。开发机提供其所在平台的实测证据，其余平台在对应环境补齐。
2. **边界保持**：越界请求（启用、删除、回滚、脚本执行、浏览器操作）被拒绝且无副作用；无效流程零写入；所有经本机通道保存的流程均未启用；没有用户操作就不会发生启用。
3. **结果可信**：未安装时交付失败；保存请求发出后断线或超时为结果未知，先读回核对再决定重试；成功报告与扩展读回一致，用户不会被告知不存在的保存结果。
4. **旧通道收敛**：AI 不经导入页逐控件导入流程；导入页仅承担保存后摘要与启用展示；相关 Skill 指引不引导浏览器导入操作。
5. **历史可回滚**：同一流程连续成功保存超过 10 次后仅保留最近 10 个版本；用户从流程详情选旧版本回滚后，内容恢复且状态为未启用，原当前内容仍在上限内可找回；失败时不出现部分覆盖。

## 6. API 相关约束

**适用性**: 适用（能力边界与访问控制原则）

- **接口能力范围**：本功能不引入网络服务或对外 HTTP API；新增的是扩展与本机程序之间的本机消息能力，范围限于流程读取、校验、保存、替换四类，与既有导入路径同级校验。不暴露启用、删除、回滚、任意脚本执行或浏览器操作；版本历史由扩展本地管理。（方法集与四类能力的映射：`ping` 承载连通验证（FR1），`flow.read`/`flow.validate`/`flow.save`/`flow.verify` 分别承载读取、校验、保存/替换与结果读回；替换由 `flow.save` 携带 `flowId`+`expectedUpdatedAt` 乐观锁承载。）
- **访问控制原则**：本机程序按用户所选浏览器做用户级注册并绑定实际扩展实例；通信仅限本机当前用户作用域，不经网络，不向页面脚本开放；流程同步（data-sync feature）的数据边界不受本功能影响。
- **兼容性原则**：桌面 Chrome 114 及以上（Windows/macOS/Linux）；本机程序依赖 Skill 指引指定版本的 Node.js 运行时；对外数据契约仍是流程文件格式（受约束步骤树），格式文档与扩展校验器保持同一事实源。

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：导入页收敛为「保存后摘要 + 一键启用」展示载体，AI 不操作该页；侧边栏保持日常工作台（流程清单、开关、失败原因、输入值表单）。
- **关键路径**：新建——AI 在对话中取得用户确认 → 本机通道保存 → 扩展呈现摘要与「启用」一键卡 → 用户本人点击启用；修订——用户从流程详情发起「用 AI 优化」→ 原流程暂停 → AI 经本机通道读取原流程、验证修订并取得对话确认 → AI 发起替换 → 用户本人重新启用。
- **历史入口**：流程详情显示本机可回滚版本；用户选择旧版本、核对后确认回滚，扩展显示恢复结果和未启用状态。版本历史与流程执行失败摘要明确区分。
- **状态反馈**：保存成功/拒绝原因（含具体条目）、启用状态、本机通道失败原因（未就绪、断线）对用户清晰可见；对 AI 以真实结果返回。
- **界面语言**：沿用英语主语言 + zh 完整翻译的既有体系；新增文案纳入同一 i18n 边界。
- **数据可见性**：敏感值脱敏与失败摘要不保存页面业务值的既有约束继续适用于本机通道的摘要与状态展示。
- **兼容性**：Chrome 114+；本功能不新增浏览器支持范围。
