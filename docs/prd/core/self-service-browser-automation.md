# 自助浏览器局部自动化（外部 AI 验证闭环版） 产品需求文档 (PRD)

**创建时间**: 2026-09-24
**优先级**: P0
**发布时间**: 2026-09-24

> 本 PRD 为外部 AI 验证闭环版（DEC-self-service-browser-automation-008）：验证"外部 AI 验证 → 流程固化 → 日常执行"完整闭环并采集试验证据；内部试验验证工具定位，不承诺对外发布、全站点可用或产品化。
流程以受约束步骤树表达（可声明同站顺序跨页），由扩展统一运行期执行；提交类动作按业务实例防重复。每条流程自带站点域名，启用只由用户操作。流程详情不提供通用预演入口；自动执行保持页面静默。实际触发失败后，侧边栏仅保留每条流程最近一次失败的节点、循环位置、环节和简短原因，成功后清除，不提供执行历史。

## 2. 范围界定

### 2.1 包含功能
- **Agent Skill 交接包**（随仓库分发，用户装入自有 AI 工具）：流程引导（探索→验证→产出流程→经本机通道交付扩展）、Chrome DevTools MCP 配置指引、流程格式文档、完整示例与安全边界说明（DEC-009、DEC-013、DEC-014）
- **流程交付（AI 本机通道，唯一交付通道）**：AI 产出流程文件后经 Chrome Native Messaging 本机通道交付扩展校验与保存——与验证操作处于同一桌面环境，无人工搬运，扩展导入页不经 AI 操作；不提供面向用户的手动导入（文件/粘贴）通道（DEC-015 通道条款由 DEC-support-native-messaging-001 承接，交付语义见 [`core/support-native-messaging.md`](support-native-messaging.md)）
- **用户自选站点**：站点、页面、触发条件由用户指定（DEC-007）；每条流程自带站点域名，内容脚本只为存在流程的站点动态注册（站点集合随流程增删自动同步，安装时统一获得 http/https host 权限）
- **两类触发**：字段选择/输入变化后联动；进入指定页面后执行受约束步骤树（页面判定由 URL 特征与可选页面内容特征共同构成）
- **受约束步骤树（DEC-019）**：流程以流程表达——读取页面数据（组列表、编辑态、勾选态、行记录等）、条件分支（已编辑/已勾选则跳过）、有界循环（逐包装组处理）、带截止时间的只读等待（元素出现、数据稳定、保存完成）、业务断言（行集合非空且数值有效）与白名单动作（设置文本、选择下拉项、勾选/取消、点击）；运行期数据引用为结构化引用而非可执行字符串，扩展不接收任意代码、表达式或脚本
- **同站顺序跨页（可选声明，DEC-cross-page-flow-001）**：流程可声明入口页与有序的后续声明页（每页特征指纹），步骤树中可声明"跳转后到达某声明页并继续"；跳转仅由既有白名单点击动作触发（含新标签页打开的同站下一页）；同一次运行跨页面连续直到终态，数据、循环进度与执行预算跨页延续；意外中断保守取消（详见 [`core/cross-page-flow.md`](cross-page-flow.md)）
- **自动动作范围**：设置文本、选择下拉项、勾选/取消、点击，以及保存/提交/确认类动作（DEC-010）；启用后触发即运行，不要求首次在场验证或逐次确认
- **防重复护栏（提交类动作的配套约束，按业务实例）**：带提交类动作的流程声明可读取的业务实例标识，执行前以 `站点+流程+业务实例` 原子占用；失败或结果未知不自动解除占用；已处目标状态即跳过；任何失败保守中止且不自动重试
- **执行预算（DEC-019）**：引擎设置不可被流程放大的硬上限——静态节点数、嵌套深度、循环项数、总执行节点数、单次等待时长与整次运行时长；流程只能取更小预算
- **失败原因可见**：实际触发失败后，流程清单与详情显示最近一次失败的节点、循环位置、环节与简短原因；成功后清除，不展示执行历史
- **流程管理**：全部流程清单、查看、修改名称与流程输入值（输入项能力定义见 [`core/form-support.md`](form-support.md)）、暂停/恢复（暂停即取消当前执行）、按流程独立开关；步骤内容由外部 AI 基于原流程重新验证，经本机通道校验后覆盖原流程
- **安装使用说明**：首次打开侧边栏展示使用说明与排除平台声明（DEC-011）
- **受控测试页**：本项目提供含表单、下拉、提交按钮与页面内重载行为的本地测试页，以及模拟异步 DOM、多包装组、保存信号与货件预览的装箱受控页，承载楔子试验、流程验收与重复触发验证

### 2.2 不包含功能 (Out of Scope)
- 扩展内 AI 对话、模型 API 调用与密钥配置；扩展自行生成流程（DEC-009）
- 用户手动导入（文件选择/粘贴）作为产品通道——交付唯一入口为 AI 经本机通道，不为其设计、引导或验收（DEC-015 手动导入排除条款继续有效，通道条款见 DEC-support-native-messaging-001）
- 扩展内流程起草（含自然语言描述与页面点选创建路径）——由"外部 AI 产出 + 本机通道交付"取代（DEC-009、DEC-013）
- 扩展侧 MCP 服务与独立命令行入口（DEC-013）；本机宿主作为流程交接通道已由 [`core/support-native-messaging.md`](support-native-messaging.md) 承接（DEC-013 宿主排除条款由 DEC-support-native-messaging-001 取代）
- 运行时站点封禁——排除平台仅作声明，由用户自行遵守（DEC-011）
- 强制首次在场验证或逐条审阅；AI 代为启用流程（DEC-014）
- 完整 RPA、任意 AI 生成代码直接执行、无人值守跨页调度、跨页流程编排
- **跨站点串联、跨标签页流程编排、并行节点、可视化流程编排器（DEC-019；其"跨文档续跑"排除条款已由 DEC-cross-page-flow-001 部分取代）**：流程可声明同站顺序跨页（见 [`core/cross-page-flow.md`](cross-page-flow.md)），但限定单一站点域名，且不存在同时或交替操作多个标签页的流程步骤（新标签页打开的声明页只是顺序继续）；不保存可恢复的运行快照
- **自动重试与自动回滚（DEC-019）**：失败/超时/取消保守停止，部分完成的操作保留在页面上由用户接手，不自动补偿
- **非当前格式流程的迁移或兼容执行（DEC-019）**：不做迁移与静默转换；携带非当前 schemaVersion 的文件一律整体拒绝，指引按当前格式重新生成导入
- 企业管理、组织层级与审计（流程共享与团队协作已由 data-sync feature 承接交付，见 [`core/data-sync.md`](data-sync.md)）
- 删除、支付、权限变更等未获本轮确认的其他不可逆动作
- 对所有站点可用的事实担保、对第三方平台使用流程的事实认定、公开商业发布与定价（DEC-008）
- Firefox 等非 Chrome 浏览器

### 2.3 依赖项
- 用户自有 AI 工具（如 Claude Code、Codex CLI），需支持 Agent Skills 与 MCP 配置
- Chrome DevTools MCP（用户自行安装配置）：受控测试页验证使用其默认独立浏览器环境；连接日常 Chrome 真实会话需较新的 Chrome 版本并逐次人工确认，或在独立环境内登录目标站点
- AI 流程交付要求本机交接环境就绪：扩展安装在用户所选浏览器内，且本机宿主已按 oncewise-setup 完成用户级安装与连通验证（安装与连通语义见 [`core/support-native-messaging.md`](support-native-messaging.md)）
- 日常使用的 Chrome 浏览器（侧边栏能力要求 Chrome 114 及以上）
- 本项目提供的受控测试页（本地静态页面，无外部服务依赖）

## 3. 需求概述

### 3.1 功能描述
已经使用 Codex、Claude Code 等 AI 工具的人，在自有工具中描述网页流程，AI 借 Chrome DevTools MCP 在浏览器中探索并先验证操作；验证通过后，AI 按本项目流程格式（受约束步骤树）产出结构化流程文件，并经本机通道交付扩展（见 [`core/support-native-messaging.md`](support-native-messaging.md)），扩展负责校验、持久化、可读摘要与按流程独立开关；用户启用流程后，日常进入指定页面或字段变化时自动执行，包括保存/提交/确认类动作（受按业务实例的防重复护栏约束）。流程能够表达真实业务流程所需的读取、判断、循环、等待与校验——例如商品装箱：逐包装组检查编辑态、勾选、加载箱规、校验行数据、保存，全部组完成后确认并等待结果页面。实际触发失败后可在侧边栏查看原因；运行可因暂停、删除或离页而取消。

本版的核心目的是验证"外部 AI 验证 → 流程固化 → 日常执行"闭环（DEC-008）：一名目标用户能否不依赖开发者，把一次验证成功的操作固化为可开关流程并可靠复用；证据未取得前不扩大范围、不启动产品化。

### 3.2 关键特性
- **AI 在用户工具中**：沟通、探索与验证由用户自有 AI 工具承担；本项目提供 Skill 交接包，扩展只负责流程运行闭环（DEC-009）
- **流程是数据不是代码**：流程为结构化流程数据，经扩展全量结构校验（节点种类、变量引用、预算）后方可保存；运行期数据引用为结构化引用（如 `{ "ref": "vars.rows" }`），受约束运行期执行白名单能力，不执行 AI 生成的代码或表达式
- **本机通道交付、默认关闭**：AI 经本机通道交付流程（不经扩展导入页操作），保存即未启用；启用只能由用户主动操作（DEC-015 默认关闭条款继续有效；交付通道见 DEC-support-native-messaging-001）
- **流程站点驱动注入**：每条流程自带站点域名；内容脚本只注入存在流程的站点，站点集合随流程增删自动同步（安装时统一获得 http/https host 权限，无按站授权步骤）
- **两类触发**：字段变化联动与进入页面流程，覆盖用户给出的两个核心场景
- **提交类动作 + 按业务实例的防重复护栏**：业务实例占用 / 前置状态验证 / 失败不重试（DEC-010、DEC-019）
- **失败可解释**：实际触发失败后在侧边栏显示环节、流程节点、循环位置和简短原因；保守中止
- **可取消、部分完成不回滚**：用户停止、暂停/删除流程、流程版本替换、离开目标业务流程或页面卸载时取消运行；已发生的操作保留在页面上，由用户接手

## 4. 业务流程与状态

### 4.1 业务流程
- **流程是数据，不是代码**：所有流程以结构化流程数据表达并通过全量结构校验（含控制流语义校验：节点种类、唯一 ID、变量引用与分支输出可用性、集合类型、嵌套深度、节点总量、等待截止时间与循环上限）后方可保存或启用；系统不接受、不执行 AI 生成的代码、表达式或脚本字符串——超出受约束步骤树词汇表达能力的复杂操作不固化为流程，由 AI 在浏览器中现场完成
- **AI 职责边界**：扩展内不提供 AI 对话、模型调用与密钥配置；流程文件由外部 AI 工具产出，交付由 AI 经本机通道完成（DEC-009；交付通道见 [`core/support-native-messaging.md`](support-native-messaging.md)）；扩展不提供手动导入通道
- **保存即默认关闭、确认在对话内**：经本机通道保存的流程处于未启用状态，不执行任何页面动作；保存前必须通过全量校验并向用户展示可读摘要（覆盖分支、循环与嵌套的提交类动作），提交类动作显著标注。AI 须在校验后向用户说明当前流程内容和验证范围，取得针对本次内容的明确确认后才经本机通道发起保存；扩展不在本机入口增设保存确认门禁（DEC-support-native-messaging-007）；最初提出创建需求不等于确认保存（DEC-014）。
- **已有流程优化**：用户从流程详情发起时先暂停原流程并授权限时读取，本机宿主向外部 AI 提供原流程完整内容。修订沿用同一校验与摘要；AI 说明变更及覆盖对象并取得用户对本次修订的明确确认后，才以原流程 ID 覆盖并转为未启用，不新增并行流程。若原流程在修订期间改变、重新启用或删除，则拒绝覆盖并保留当前内容。用户本人决定是否重新启用；放弃修订时原流程保持暂停。
- **启用只归用户**：启用不要求逐条审阅或首次在场验证；AI 可以导入流程，但不得代为启用流程（DEC-014）
- **注入与流程站点绑定**：扩展只对存在流程的站点注入和执行；流程删除后其站点不再注入，进行中的运行按暂停/删除语义取消
- **能力白名单与提交类语义**：允许的自动能力限于读取页面数据、设置文本、选择下拉项、勾选/取消、点击、条件判断（类型化谓词）、有界循环、带截止时间的等待与业务断言；保存/提交/确认类动作允许进入流程并在启用后自动执行（DEC-010）
- **防重复护栏（按业务实例，DEC-019）**：三类机制分开——启动防重入（来源标记、触发去抖、单运行锁）；同一业务实例防重放（执行前以 `站点+流程+业务实例` 原子占用，失败或结果未知不自动解除，浏览器会话结束后仍需页面状态门控）；同一次运行内的合法循环（按运行 ID+节点+循环项标识步骤，不同组的保存均执行，同一组的确认不因事件重复而重放）。带提交类动作的流程须声明可读取的业务实例标识，缺少可靠标识时保守拒绝启动；提交前再确认业务标识未改变
- **保守中止**：执行中遇到元素缺失、定位歧义、集合变化、校验/断言失败、等待超时或预算超限时立即停止，不盲目重试、不回滚用户或已完成的操作（失败环节与节点在侧边栏可见）
- **循环与预算控制**：自动动作不得再次触发自身或形成互相触发的连锁（自动动作带来源标记）；合法循环由结构预算、循环项数、执行次数与总时长控制，不因动作去重被误伤
- **运行取消与部分完成**：暂停/删除流程、流程版本替换、离开目标业务流程或 document 卸载时，取消当前运行及未启动的排队任务；取消只能阻止后续行为，已发生的副作用保留在页面上，不自动补偿或重试；暂停后再次启用不从中间节点自动续跑
- **数据边界**：侧边栏中的流程内容对敏感值脱敏；失败摘要只保存节点与机器原因，不保存页面业务值；运行期读取的页面数据只在本机内存中出现，不离开设备；扩展内无 AI，不存在向模型发送页面数据的问题
- **排除平台声明**：安装后首次打开展示使用说明，声明淘宝、亚马逊等本产品声明不支持辅助操作的平台不得使用；仅展示，不做运行时封禁，由用户自行遵守；该声明不构成对第三方平台流程的事实认定（DEC-011）
- **多流程边界**：本轮以单流程场景为验收范围；多流程同页并存时的执行顺序与相互影响不纳入本轮验收

### 4.2 关键状态与异常
- 流程状态：未启用（导入默认）→ 已启用 ⇄ 已暂停（暂停取消当前执行）
- 交付结果状态：通过（保存为未启用流程）；拒绝（说明原因，不保存任何部分）；结果未知（保存请求已发出但未收到扩展结果，不推断写入结果，先读回核对扩展状态——见 [`core/support-native-messaging.md`](support-native-messaging.md)）
- 运行终态：成功（completed）；跳过（skipped：占用未解除、已处理或防重复判定，附明确原因）；失败（failed：触发/定位/动作/验证/断言/等待/预算，携带节点 ID、循环项标识与最后成功节点）；已取消（cancelled：用户停止、暂停/删除流程、流程替换、离开目标业务流程或页面卸载）
- 业务实例占用状态：未占用 → 已占用（执行前占位；失败或结果未知不自动解除）
- 异常与兜底：
  - 流程文件不符合格式、包含不支持节点、非法变量引用或越界预算 → 交付整体拒绝并说明原因，已有流程不受影响
  - 携带非当前 schemaVersion 的文件 → 拒绝交付并提示版本不支持，指引按当前格式重新生成导入（DEC-019）
  - 页面改版或异步加载导致定位失败/定位歧义 → 保守中止并指明环节与节点，流程保持原状态
  - 等待的目标最初不存在、随后出现 → 等待成功后继续，不因初始缺失失败
  - 流程中途失败或取消 → 已执行操作不回滚、剩余节点不继续；页面留给用户接手
  - 同一业务实例的重复触发、多标签页竞争 → 同一业务只有一个执行者；已发出的提交不重复

## 5. 功能需求

### 5.1 核心需求
- **FR1 Agent Skill 交接包**：提供可装入用户自有 AI 工具的 Skill，含流程引导、Chrome DevTools MCP 配置指引、流程流程格式文档与示例；流程格式文档与扩展校验器保持同一事实源
- **FR2 流程交付（AI 本机通道）**：AI 经本机通道交付流程候选，扩展执行全量校验（结构 + 控制流语义 + 预算）并给出可读摘要（覆盖分支、循环与嵌套的提交类动作显著标注）；AI 向用户说明内容与验证范围，取得对话内对本次内容的明确确认后才经本机通道保存为未启用流程；用户要求修改或未确认时停在保存前。校验失败（含未知 schemaVersion）整体拒绝并说明原因；不提供用户手动导入通道（交付语义见 [`core/support-native-messaging.md`](support-native-messaging.md)）
- **FR3 流程启用**：按流程独立启用/关闭；启用不设首次验证门禁，启用操作仅限用户本人；启用支持在导入页面一键完成——保存后即时呈现「核对摘要→启用」确认卡，一次点击完成启用（DEC-016）
- **FR4 字段变化联动执行**：字段选择/输入变化触发受约束步骤树（含读取、条件与白名单动作），自动执行保持页面静默（2026-09-28 用户裁定移除执行 toast，页面自身状态变化即结果），具备循环防护
- **FR5 进入页面执行流程**：按 URL 特征与可选页面内容特征判定命中页面，命中即执行受约束步骤树；流程支持读取（标量、状态、集合、行记录）、条件分支、有界循环（遍历读取到的实际集合）、带截止时间的只读等待（可等待最初不存在的目标）与业务断言；同次页面进入至多启动一次（声明业务实例标识的流程按业务实例计：同一页面进入内切换业务实例时，各业务实例可分别启动一次，见 §4.1 防重复护栏）；非命中页面零动作；流程可声明同站后续页与跳转声明，运行在到达的声明页继续直到最后一页（跨页语义见 [`core/cross-page-flow.md`](cross-page-flow.md)）
- **FR6 提交类动作与按业务实例的防重复护栏**：保存/提交/确认可自动执行；带提交类动作的流程（含嵌套于分支与循环中的）声明业务实例标识并执行前原子占用；占用未解除或已处理则跳过并说明原因；失败或结果未知不自动解除占用；前置状态已达标即跳过；失败保守中止不重试；业务实例占用跨页面保持，继续执行时复核业务标识（跨页防重放见 [`core/cross-page-flow.md`](cross-page-flow.md)）
- **FR7 实际触发失败原因**：每条流程在浏览器会话内只保留最近一次自动触发失败的节点、循环位置、环节与简短原因；流程清单可展开查看，详情可直接查看；成功后清除，正常防重复跳过不报错；不提供通用预演入口和执行历史；跨页流程的失败明细含页定位
- **FR9 流程管理**：流程清单、查看、修改名称与流程输入值、暂停/恢复（暂停即取消当前执行且恢复后不自动续跑）、独立开关；从详情发起「用 AI 优化」时先暂停原流程并授权限时读取，AI 经本机通道读取现有定义、在目标页验证受影响步骤，经同一校验并取得用户对变更的明确确认后以原 ID 覆盖为未启用状态；修订期间原流程被改动、启用或删除时拒绝覆盖
- **FR10 安装使用说明**：首次打开展示使用说明与排除平台声明，确认后进入主界面，可再次查看
- **FR12 运行取消与预算**：用户停止、暂停/删除流程、流程版本替换、离开目标业务流程或页面卸载时取消运行（含轮询与未启动任务）；引擎硬预算（节点数、嵌套深度、循环项数、执行次数、等待与运行时长）不可被流程放大，超限有原因地停止

> 编号沿革：FR8、FR11 为草稿期条款（执行日志与试验证据留痕），未随发布保留；本 PRD 沿用已发布条款编号，不重排空洞。

### 5.2 验收目标
以下为本轮内部试验的决策门槛（源自 Decision Brief Kill Criteria 与 DEC-008）：

1. **闭环可走通**：至少 1 名目标用户在自选受控测试页，经自有 AI 工具与 Chrome DevTools MCP 验证操作、由 Skill 产出流程文件并经本机通道交付扩展、用户核对摘要后一键启用（于导入页面完成，无跨界面往返，DEC-016）、重新进入页面后自动执行，全程无需开发者修改代码；若必须开发者介入才能完成交接，或 AI 本机通道交付在受控验证中不可行，停止当前路线并回到 Decision 重评
2. **页面命中与隔离正确**：流程在两个不同的受控页面命中/不命中行为正确，包含页面刷新与重复进入场景；若无法约束错误页面执行，不扩大自选站点范围
3. **提交类执行次数可控**：在受控测试页模拟提交、确认、重复触发、刷新与页面内重载，同一业务实例内提交类动作实际执行次数为 1 或 0（跳过），以受控页动作记录核对一致；多标签页对同一业务竞争时只有一个执行者；若不可控，收缩提交类动作范围并回到 Decision 重评
4. **失败可解释**：真实触发失败后，侧边栏能明确指出失败节点（含第几组、哪一步）、环节与简短原因；成功后旧错误消失
5. **流程执行正确（受控装箱页）**：单组与多组装箱按序完成（编辑、全选、加载、校验、保存、每组保存完成后再进下一组、最终确认一次）；已编辑/已勾选时跳过对应动作且不把已勾选切回；无效数据（缺失、空值、0、非数值、无行）不保存该组、不处理后续组、不确认；等待最初不存在的元素能成功；取消（暂停、离页）后不再发生副作用；旧 schema 与非法引用在导入时整体拒绝

## 6. API 相关约束

**适用性**: 适用（能力边界与兼容性）

- **接口能力范围**：本 feature 自身不引入网络服务与对外 API（data-sync feature 的自建同步服务见 [`core/data-sync.md`](data-sync.md)）；对外唯一数据契约是"流程文件格式"（受约束步骤树）——结构化数据而非代码，由外部 AI 工具按格式文档产出、由扩展端校验器全量校验（结构、控制流语义与预算）。流程格式文档与扩展校验器必须保持同一事实源，防止交接格式漂移
- **访问控制原则**：无服务端、无租户/realm 数据边界；流程保存在用户本机浏览器存储内，流程启用状态不出本机。脚本数据（名称、备注与版本化流程内容）可经 data-sync feature 存储于团队自建的同步服务器，其数据边界以 data-sync PRD 为准（见 [`core/data-sync.md`](data-sync.md)）
- **兼容性原则**：流程交接包遵循 Agent Skills 开放格式（Claude Code、Codex CLI 原生支持）；浏览器兼容见 §7；外部 AI 工具与 Chrome DevTools MCP 均为用户侧工具，不属于本项目依赖树，其变化不改变扩展端产品边界

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：单击浏览器工具栏图标直接打开常驻侧边栏工作台并落在流程页（无 popup 中转）；不限定特定站点页面
- **扩展导入/管理页面**：扩展提供一个可经浏览器直接打开的导入与管理页面（保存后摘要、流程清单与独立开关、保存后「启用」一键确认），作为保存后摘要展示与用户本人启用的载体（DEC-016）；流程交付经本机通道完成，AI 不操作该页面（见 [`core/support-native-messaging.md`](support-native-messaging.md)）；侧边栏仍为日常工作台，其「设置」页保留打开导入页面的入口
- **侧边栏工作台**：流程清单与开关、最近一次失败原因、使用说明集中于侧边栏；流程交付经本机通道完成（AI 不操作扩展页面），保存后摘要与一键启用在导入页面呈现，首轮流程无需进入侧栏（DEC-016）；data-sync feature 的「同步」页签同在侧边栏（见 [`core/data-sync.md`](data-sync.md)）
- **首次打开**：首次打开侧边栏展示使用说明（支持边界、排除平台声明、自动执行语义、本地优先数据边界），用户确认阅读后进入主界面；之后可从侧边栏再次查看
- **界面语言**：扩展 UI 以英语为主语言（en 默认 catalog），内置 zh 完整翻译；manifest 名称与描述经 `_locales` 提供双语
- **页面内交互**：自动执行保持页面静默（无 toast），结果以页面自身状态变化呈现
- **状态反馈**：导入校验通过与拒绝原因、启用状态、实际触发失败环节提示清晰可见
- **数据可见性**：联系电话等敏感值在侧边栏脱敏展示；失败摘要不保存页面业务值
- **兼容性**：日常使用的 Chrome 浏览器（侧边栏要求 Chrome 114+）；真实站点会话验证路径（连接日常 Chrome）要求更新的 Chrome 版本并逐次人工确认，或使用独立浏览器环境内登录；本版不验证其他浏览器
