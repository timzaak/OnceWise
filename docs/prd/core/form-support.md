## 2. 范围界定

### 2.1 包含功能

- AI 生成流程时定义该流程需要用户提供的输入项及其名称、类型、必填性；单选和多选项还定义可选择的候选值。流程详情按定义显示填写表单，用户填写、修改并保存本机值。
- 首版输入类型：文本、数字、单选、复选、日期、时间、多选。流程可包含多项输入，同一项可由流程中多个步骤引用。
- 流程按现有的页面进入或字段变化条件自动触发时，使用启动时已保存且有效的本机输入值；同一次流程的后续步骤使用同一组值，运行期间保存的新值从下次触发生效。
- 必填项缺失或输入值无效时跳过本次执行，流程详情指明具体项目；选填项缺失本身不阻止执行。
- 输入项定义可随流程共享；用户填写值保存在本机，后续触发复用，不随同步空间中的流程共享。

### 2.2 不包含功能（Out of Scope）

- 文件上传及上述七种类型以外的输入项。
- 在每次自动触发时弹出填写界面，或要求用户手动启动流程。
- 把本机填写值同步给其他空间参与者、作为共享流程内容或执行历史保存。
- 跨 document 续跑、跨标签页传递运行输入，或改变既有自动化动作与提交防重复边界。

### 2.3 依赖项

- 现有流程详情、AI 生成与导入流程、页面进入和字段变化触发、受约束步骤树及本地流程存储。
- 已发布的脚本同步能力：共享的是流程定义，空间参与者在各自本机填写输入值。

## 3. 需求概述

### 3.1 功能描述

一些自动化流程需要在运行前取得由用户决定、但不一定存在于目标网页上的数据。AI 在流程中声明所需输入项；用户提前在扩展的流程详情填写并保存。流程仍按既有条件自动触发；启动时读取本机已保存值，并在整次流程中供不同步骤重复使用。用户随后修改输入值，不影响已启动的流程，只影响后续触发。

### 3.2 关键特性

- **流程定义表单，用户填写值**：输入项的含义与流程由 AI 在流程中定义；具体业务值由本机用户维护。
- **跨步骤复用**：同一输入值可在多个流程步骤中引用；文本、数字、选择及日期时间等值按其输入类型使用。
- **自动触发前校验**：缺少必填项或值无效时零页面动作，并在流程详情给出可修正的项目。
- **本机数据边界**：输入项定义可以共享，填写值不随流程同步。

## 4. 业务流程与状态

### 4.1 业务流程

1. 只有流程声明了输入项时，流程详情才显示对应表单；未声明输入项的已有流程不需要用户额外配置。
2. AI 声明每项输入的名称、七种受支持类型之一、必填或选填；单选、多选还声明候选值。用户只能填写或选择值，不通过流程详情改变输入项定义。
3. 保存时检查值是否符合声明类型与候选范围；无效值须指出具体项目，不能成为后续执行的有效输入。必填项可以暂时留空保存，但自动触发时不得开始执行。
4. 自动触发时先检查当前流程的本机输入：必填项缺失或已保存值无效，跳过本次执行，且该流程不产生页面动作。流程详情持续显示缺失项或错误项；补齐并保存后，下一次触发重新判断。
5. 选填项为空时仍可启动；流程必须能按“未填写”状态处理该项，不得把它当作已填写的业务值。若后续步骤要求实际值而缺失，按既有流程失败流程保守停止。
6. 一次流程从启动至结束使用同一组启动时的输入值。用户运行中修改并保存时，本次流程不切换值，新值仅用于下次启动。
7. 用户填写值按流程保存在本机，流程被删除时不再供该流程复用；同步空间只共享输入项定义。拉取的流程在新设备上没有原用户填写值，本机必填项未补齐时按流程 4 跳过。
8. 现有“流程导入默认关闭、启用仅由用户操作”和“提交类动作按业务实例防重复”的业务流程继续适用。输入表单的存在不等于用户授权启用或提交。

### 4.2 关键状态与异常

| 状态或情形 | 用户可见结果 | 执行结果 |
|---|---|---|
| 输入项未填写或选填项为空 | 流程详情显示未填写状态 | 缺少必填项则跳过；仅缺少选填项可启动 |
| 值无效 | 流程详情指出具体错误项 | 无效值不可用于后续执行；触发时跳过 |
| 值有效并已保存 | 流程详情显示已配置状态 | 下次触发读取该组值 |
| 流程正在运行且用户保存新值 | 流程详情显示新保存值 | 当前流程沿用启动时值；下次触发使用新值 |
| 拉取含输入项定义的共享流程 | 流程详情显示输入项，本机值为空 | 补齐必填项前触发跳过 |

## 5. 功能需求

### 5.1 核心需求

- **FR1 输入项定义**：流程可声明多项有名称、类型、必填性及选择候选值的输入项。导入和拉取时，扩展只接受受支持的定义；不支持或不合法的定义整体拒绝并说明原因，已有流程不受影响。
- **FR2 流程详情填写**：流程详情按定义呈现文本、数字、单选、复选、日期、时间和多选输入；用户可保存、修改本机值，并查看缺失或无效项。
- **FR3 触发前检查**：自动触发时检查必填与有效性；缺少必填项或值无效则跳过本次执行，零页面动作，在流程详情提供可定位的错误项目。
- **FR4 流程复用**：同一次流程中不同步骤可以引用同一输入值；整次流程使用启动时的值，新保存值在下次触发生效。
- **FR5 同步边界**：向同步空间保存脚本和从空间拉取脚本时保留输入项定义，但不传输本机填写值；每位空间参与者在本机独立填写。

### 5.2 验收目标

1. 用户为流程保存一项输入值后，在一次自动触发的受控流程中，两个不同步骤均使用该值并产生对应的页面结果；用户修改保存后，下一次触发使用新值。
2. 流程运行期间修改保存值，当前流程的后续步骤仍使用启动时旧值；下次流程使用新值。
3. 必填项缺失或输入值无效时自动触发产生零页面动作，流程详情准确列出缺失或错误项目；仅选填项缺失不阻止启动。
4. 共享流程被另一位参与者拉取后，对方能看到输入项定义，但看不到原用户填写值；补齐本机必填项后可按自己的值运行。

## 6. API 相关约束

**适用性**：不适用。

本功能不新增面向外部的接口能力；沿用现有流程导入与同步能力。同步数据边界见 §2.1 和 §4.1：只共享输入项定义，不共享用户填写值。

## 7. 前端／交互约束

**适用性**：适用。

- **页面入口**：侧边栏流程详情展示 AI 声明的输入表单；仅有声明输入项的流程显示该区域。
- **关键路径**：查看流程详情 → 填写或选择值 → 保存 → 保持流程既有启用语义 → 流程自动触发并使用保存值。
- **反馈**：保存时指出无效值的具体输入项；自动触发因必填缺失或无效而跳过时，流程详情指出修正项目。运行中修改值应让用户知道新值从下次触发生效。
- **可见性**：本机用户可编辑该流程的填写值；空间参与者只能在各自本机查看或编辑自己的值，不能经同步查看他人的值。
