# Herald 鉴权支持（herald-support）产品需求文档 (PRD)

**创建时间**: 2026-10-08
**优先级**: P0
**发布时间**: 2026-10-09

> 本 PRD 是 [`docs/prd/core/data-sync.md`](../core/data-sync.md) 的部署鉴权扩展：在空间密钥模型之外，为 oncewise-ai-sync 服务端增加一道**服务级 Herald 访问门禁**，默认启用；显式配置才回落无鉴权模式（该模式行为完整保留）。本 feature 行使 data-sync「无账号空间模型」决策的重开条件（出现不可信圈子的访问控制需求），但只加门禁、不引入空间所有权/成员/审计——data-sync 正式 PRD 的「无账号」表述据此限定为**空间模型无账号，部署层默认带服务级门禁**（见其文首 2026-10-09 边界修订）。
> 术语：**登录** = 在启用鉴权的服务器上经 Herald 授权窗口完成认证并持有访问凭证；**门禁** = 服务端对业务访问的前置用户身份校验层，与空间密钥（空间寻址）正交；**鉴权模式 / 无鉴权模式** = 服务端的两种运行模式。

## 2. 范围界定

### 2.1 包含功能
- **服务级 Herald 访问门禁（默认启用）**：启用鉴权时，oncewise-ai-sync 的全部业务访问（空间、脚本、版本）前置用户身份校验，未通过即拒绝；健康探针、API 契约描述与鉴权流本身保持公开
- **双运行模式**：默认 Herald 鉴权——未显式选择模式且缺 Herald 配置时服务端启动即失败（fail-fast）并给出完整配置指引；显式配置无鉴权模式 = 现状原样，保留为内网/本地开发的逃生通道
- **扩展登录流**：连接服务器后按其公开的模式信息自适应呈现；启用鉴权时经授权窗口完成 Herald 登录、凭证保存在本机扩展存储、过期自动续期、彻底失效引导重登；登出与服务器切换清除登录态（一切经 oncewise-ai-sync 代理，扩展不直连 Herald）
- **鉴权状态的异常反馈**：未登录、需重登、鉴权暂不可用等状态与原因在同步区可见、可重试；本地优先韧性不回退
- **data-sync 基线表述修订**：「无账号」边界限定为空间模型层面（服务端不因门禁引入账号-空间关联），见文首说明

### 2.2 不包含功能 (Out of Scope)
- 空间级所有权、成员管理、角色分级、邀请、审计日志（不引入；Herald 用户身份不与空间关联、不在服务端持久化）
- 权限点、角色、权限列表校验（含读/写分级、按脚本或按空间授权）——有效登录即可使用同步，空间内对等读写仍由空间密钥承担
- 扩展直连 Herald 或内置 Herald 地址（授权与续期经所连服务器代理；用户改配任意自建服务器无需扩展发版）
- 无鉴权模式的任何行为变更（逃生通道语义冻结：与升级前一致）
- Herald 侧能力的承接与产品化：注册页定制、计费、多 realm 管理、令牌管理界面（属 Herald 控制台的部署侧配置动作，交付物仅文档化准备步骤）
- 服务端的用户身份资料存储或同步（身份只存在于校验过程的瞬时上下文）
- 移动端与非 Chrome 浏览器（含 Firefox 授权窗口适配）
- data-sync 既有空间、脚本、版本语义的任何变更

### 2.3 依赖项
- data-sync 已发布能力与语义基线（本 feature 只加前置门禁，不改其业务规则）
- 一个可用的 Herald 实例与部署侧控制台配置（realm、client app 的回调地址注册；无需 API key、权限点或角色）——部署动作，交付物为文档化的准备步骤
- Chrome 授权窗口（identity）平台能力：manifest 新增 `identity` 权限
- 服务端公开的模式探测能力（扩展据此自适应呈现，不内置任何 Herald 地址）

## 3. 需求概述

### 3.1 功能描述
data-sync 的空间密钥解决"空间内谁能对等读写"，但服务端暴露到不可信圈子（公网、半公开环境）时，缺少"谁有资格访问本服务"这道门：任何拿到或截获空间码的人都能直接读写。herald-support 为自建服务端接入 Herald 鉴权作为服务级门禁：默认部署即要求使用者经 Herald 登录、持凭证访问业务能力，一次登录覆盖该服务器上全部空间；空间协作模型（客户端生成 ID 与密钥、持钥对等读写）原样保留。显式配置无鉴权模式时服务端与现状完全一致，适用于内网与本地开发场景。扩展侧在同步区承接登录、登出与状态反馈，对无鉴权服务器零感知。

### 3.2 关键特性
- **默认带门禁（fail-fast）**：不配置就拒绝启动并给出完整指引，杜绝"忘了配置"的裸奔部署；显式选择才无鉴权
- **门禁与空间模型正交**：登录是服务级、不区分空间；不引入账号-空间关联、成员或审计——互信圈子的空间语义不变，只是把"进圈子的门"从空间码提前到用户身份
- **扩展零内置**：不内置任何 Herald 地址，一切经所连服务器发现；用户改配任意自建服务器无需扩展发版
- **本地优先不回退**：未登录、凭证失效或门禁故障只影响同步通道；本机流程、已拉取内容与空间清单照常（承接 data-sync 本地优先原则）
- **fail-closed**：鉴权依赖不可用时拒绝服务、绝不放行未认证访问（架构性取舍，见 §4.1）

## 4. 业务规则与状态

### 4.1 业务规则
- **模式规则**：服务端两种运行模式互斥——鉴权模式（默认）与无鉴权模式（显式选择）。未显式选择且缺 Herald 连接配置时启动失败，报错列出所缺配置项与两条出路（补齐配置 / 显式无鉴权）；不存在隐式降级
- **门禁范围**：启用鉴权时，全部业务访问（空间、脚本、版本的读写）前置身份校验；公开范围仅限健康探针、API 契约描述与鉴权流本身。门禁先于空间密钥校验，两层都通过才放行——空间码错误提示不泄露给未登录者
- **登录规则**：有效 Herald 登录即可使用同步；不校验权限点、角色或权限列表，不要求 `sync:view`；空间密钥规则保持原样
- **身份规则**：服务端不保存用户身份资料、不记录"哪个用户访问了哪个空间"、无审计；用户标识仅存在于校验过程的瞬时上下文，不缓存登录结论
- **凭证规则**：访问凭证经 Herald 授权获得、短时效；续期由刷新凭证轮换完成，每次轮换后旧刷新凭证立即失效（丢失/泄露影响受限，重新登录即恢复——本地优先取舍）；凭证不出现在 URL 或服务器访问日志
- **账号停用生效**：每次业务访问重新确认登录有效性；Herald 已完成账号停用后，下一次校验即拒绝。角色、权限的增删不影响同步访问
- **fail-closed**：Herald 不可用时业务访问拒绝并明确提示"鉴权暂不可用"，不降级放行（放行等于绕过门禁）；无鉴权模式不依赖 Herald、不受影响
- **登录态边界**：登录态属"服务器 + 本机扩展"维度——随服务器地址切换清除，不随空间操作变化；登出仅清登录态，不动空间清单、本机流程与已拉取内容
- **扩展自适应**：扩展按服务器公开的模式信息呈现；无鉴权服务器不出现任何登录 UI（零感知），其全部行为与升级前一致

### 4.2 关键状态与异常
- 服务端模式状态：鉴权启用（正常运行）/ 启动失败-缺配置（指引可见）/ 无鉴权（现状）
- 扩展登录状态：未登录（该服务器要求登录时）/ 登录中 / 已登录 / 需重新登录（凭证彻底失效）
- 同步操作状态（在 data-sync 既有状态之上扩展）：未登录被拒（引导登录）/ 需重登（引导重登）/ 鉴权暂不可用（可重试）
- 异常与兜底：
  - 未登录时执行业务操作 → 拒绝并明确"需要登录"，引导登录；本地功能不受影响
  - 访问凭证过期 → 自动续期并重试本次操作一次，用户无感；再失败转"需重登"
  - 刷新凭证失效（轮换竞态、长期未用、账号停用）→ 清登录态、引导重新登录；本机数据与空间清单保留
  - Herald 不可用 → 业务拒绝、原因可见、可重试；恢复后无需任何重新配置即可继续；写操作超时且结果未知时先刷新列表核对结果，再决定是否重试
  - 用户账号在 Herald 侧被停用 → 下一次业务请求被拒，引导重新登录；权限或角色变化不构成拒绝理由
  - 凭证与部署 realm 不匹配 → 拒绝；报错指引部署侧检查 realm 配置（部署问题，非用户操作问题）
  - 升级迁移（默认鉴权引入）→ 既有部署未显式选择模式时启动失败并给出两条出路；发布说明含完整迁移章节

## 5. 功能需求

### 5.1 核心需求
- **FR1 服务端双模式与配置**：默认鉴权；Herald 连接参数（实例地址、realm、客户端标识、明确注册的服务端回调地址）环境变量化并入既有配置模式；缺配置 fail-fast，报错含完整配置指引；提供显式无鉴权模式开关
- **FR2 公开鉴权能力**：服务端公开鉴权模式信息（供扩展自适应）与登录所需的授权代理、续期代理能力；授权流不把访问或刷新凭证暴露给 URL 或日志（具体接口契约由技术设计承载）
- **FR3 扩展登录编排**：同步区登录入口 → 授权窗口完成 Herald 认证 → 凭证保存于本机扩展存储、已登录状态可见；登出经确认后仅清登录态
- **FR4 凭证生命周期**：访问凭证过期自动续期并单次重试原操作（不打扰用户）；续期凭证失效才清登录态并引导重登；依赖故障保留凭证并提示稍后重试；同一登录会话的并发操作共享同一次续期，避免轮换竞态导致凭证族失效；登出/切换/新登录后迟到的响应不得恢复旧登录态
- **FR5 服务器切换联动**：更换服务器地址时，既有"清空同步关联"扩展为同时清除登录态；此后按新服务器模式自适应呈现
- **FR6 状态与异常反馈**：未登录/需重登/鉴权暂不可用在同步区可见、原因明确、可重试；期间本地流程功能不受影响，进行中的运行不被重启
- **FR7 迁移与兼容**：发布说明含部署迁移路径（配 Herald 或显式无鉴权）；扩展对无鉴权服务器的行为与旧版完全一致；manifest 新增授权窗口权限带来的更新提示在发布说明中说明

### 5.2 验收目标
1. **鉴权部署协作闭环**：两名真实参与者在启用鉴权的服务器上各自登录后，完整重放 data-sync 验收目标 1/2（建空间 → 发码加入 → 存脚本 → 发新版本 → 拉取 → 本人启用），全部同步语义不变
2. **未登录不可访问**：未完成登录的客户端对业务操作的访问被拒绝并得到"需要登录"引导；期间本机流程功能照常
3. **无鉴权零变化**：显式无鉴权部署上，服务端与扩展行为与升级前完全一致（既有集成场景原样通过；不出现任何登录 UI）
4. **凭证生命周期闭环**：登录后访问凭证过期自动续期无感；彻底失效引导重登后恢复；登出与服务器切换后登录态按规则清除
5. **fail-closed 与恢复**：Herald 不可用期间同步操作明确失败、可重试，本地流程与进行中运行不受影响，无未认证放行；恢复后无需重新配置自动可继续
6. **部署可预期**：缺配置的启动失败信息可独立指导部署者完成配置（无需查阅源码）；升级路径在发布说明中完整呈现

## 6. API 相关约束

**适用性**: 适用（能力边界与访问控制原则）

- **接口能力范围**：服务端在既有空间/脚本/版本能力之外新增公开的鉴权能力——模式探测（供扩展发现服务器是否要求登录）、授权代理（引导用户到 Herald 完成认证并把凭证交回扩展）、续期代理；健康探针与 API 契约描述保持公开。具体端点与数据契约由技术设计文档承载，不在本 PRD 展开
- **访问控制原则**：启用鉴权时业务访问凭 `Authorization: Bearer` 凭证 + 既有 `X-Space-Key` 双层校验，门禁在前；用户身份校验经 Herald 完成，有效登录即可，不检查权限或角色；服务端无账号、成员、角色表，不持久化用户身份
- **错误契约**：沿用统一错误体；"未登录/凭证失效"与"空间密钥错误"以不同错误码区分，供扩展分流引导（登录引导 vs 密钥检查）；"鉴权暂不可用"单独成类（可重试、非用户操作问题）
- **realm 边界**：Herald realm 是部署级配置；用户凭证必须属于所配置 realm，跨 realm 拒绝。本方案无需 Herald API key；realm 是部署隔离边界，属于身份校验而非权限授权
- **兼容性原则**：无鉴权模式下接口行为与现状逐字一致；接口路径不带版本号（沿用既有承诺）；扩展不内置 Herald 地址，一切经所连服务器公开能力发现（用户换自建服务器无需扩展发版）

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：扩展侧边栏「同步」页签承接登录/登出入口、登录状态与"需要登录/需重登/鉴权暂不可用"提示；Herald 认证页在授权窗口（Chrome identity）中呈现，扩展不复刻登录表单
- **关键交互**：连接服务器后按其公开模式自适应——无鉴权服务器不出现任何登录 UI（零感知）；启用鉴权服务器在同步操作前引导登录；登录经授权窗口完成后自动返回扩展；登出为显式确认操作，文案明确只清登录态、不动空间与本机数据
- **状态反馈**：登录中/已登录/未登录/需重登/鉴权暂不可用状态在同步区可见；凭证过期自动续期不打扰用户；失败原因明确且可重试
- **数据可见性与安全**：访问与刷新凭证仅存于本机扩展存储，不进入流程数据、不同步、不出现在 URL；存储访问仅限受信任扩展上下文；登出或切换后迟到的登录/续期结果不得恢复旧登录态
- **国际化**：扩展 UI 以英语为主语言（en 默认 catalog），内置 zh 完整翻译；同步区鉴权文案同受 i18n 覆盖
- **兼容性**：沿用 Chrome 114+ 基线；manifest 新增 `identity` 权限，既有用户更新时会看到一次权限更新提示（迁移体验，发布说明中说明）
