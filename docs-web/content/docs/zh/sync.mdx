同步是可选的。扩展本地优先：浏览器存储是数据主体，[流程](./flows)里的一切在没有服务器时完全可用。同步只增加一件事——一个把流程以带版本脚本交给同事的地方，而且谁都不用注册账号。

## 模型

- **空间（space）**是一个脚本存放地。服务器只存储和分发结构化脚本数据，从不生成或执行流程。空间分两类，类别由服务端决定、不在界面上选择：
  - **密钥空间**由你设备上生成的一对值寻址：空间 ID 与密钥。`AUTH_MODE=none` 服务器上的空间全部是密钥空间。
  - **组织绑定空间**存在于带 Herald 登录门禁的服务器上。它没有密钥：准入是登录身份加成员资格，并带角色分级。
- **空间码**是密钥空间那对值的文本形态，`空间ID#密钥`。你用现有渠道（IM、邮件）发给同事；产品内没有通知系统。
- **邀请码**是组织绑定空间的加入凭证：管理员签发的一次性码，单次消费、24 小时有效、固定授予只读成员档。同空间可同时并存多枚。
- **脚本（script）**是进入空间的流程。把本地流程存为脚本时记录名称与备注；内容变更存为新的**不可变版本**。改名改备注不产生新版本。

密钥空间里持码者权限完全对等：读、写、改名、发布、删除。这适合小范围互信团队，它不是权限系统。密钥丢失即失去该空间——服务端不设找回渠道，这是明示的取舍。

组织绑定空间用角色替代共享密钥。创建者是**所有者**；**管理员**可写、发布并管理成员；普通**成员**只读——浏览和拉取与他人完全一致，写与管理入口在其界面上不出现。成员资格在每次请求时实时判定：移除某人后，其下一次访问即被拒，旧邀请码也不能使其重入。所有者不可被移除或降级，会使空间失去全部管理员的变更会被拒绝，所有权一步转移、原所有者降为管理员。

## 打开同步

在侧边栏的**同步**页签填入服务器地址（一个 [oncewise-ai-sync](./self-hosting) 部署，由你或你信任的人运营）。扩展先探测服务器的登录模式：

- 以默认 Herald 门禁部署的服务器会显示登录卡片；登录会打开一次服务器的授权窗口，之后会话静默续期。凭据保存在浏览器本地存储。
- 以 `AUTH_MODE=none` 部署的服务器跳过登录，直接进入空间。

## 共享一条流程

密钥空间的路径：

1. 在同步页签**创建空间**。ID 与密钥在你的设备上生成；空间注册到服务器并在本机选中。
2. **复制空间码**（空间列表里可见）发给同事。
3. 同事在自己的同步页签**粘贴空间码**。服务器验证通过后本机才记录；码不存在或不正确会被拒绝并给出原因。
4. 你这边把流程**存为空间脚本**。
5. 同事浏览空间脚本、预览某个版本的摘要，**把想要的版本拉取**到本机。

组织绑定空间（带 Herald 门禁的服务器）走邀请码，同一个页签：

1. 在同步页签**创建空间**。门禁服务器上建的就是组织绑定空间，你成为所有者；没有空间码可复制。
2. 从空间行打开**成员**，**签发邀请码**。邀请码只明文展示一次——当场复制；单次消费，24 小时后过期。
3. 同事登录同一服务器，在同一个粘贴加入框里**粘贴邀请码**，以只读成员身份加入；码无效、已用或过期会被拒绝并给出原因，本机不记录任何内容。
4. 你这边把流程**存为空间脚本**。只读成员的浏览与拉取与上面完全一致；保存、发布、改名是管理员侧操作，要让对方可写就先在成员列表里提升其角色。

拉取的脚本经过与其他导入相同的校验后，以本地流程落地，禁用态。同事自己启用，之后按该版本执行。你之后发布新版本，对方只会收到提示——不主动拉取，设备上的内容不会变。你本地未发布的修订会被标记为未发布；切换与回退手动完成。

## 忘记与删除

- **忘记**只把空间从你的设备移除——已拉取的流程与本地数据保留。两类空间相同，被移除或自主退出后也一样：条目和已拉取内容留在本机，直到你自己忘记。
- **删除**移除服务端空间并级联删除其脚本。组织绑定空间上这是管理员操作，组织、成员关系与未使用的邀请码随之失效。各方已拉取的本地内容不受影响。

## 自己跑服务器

服务器是一个跑在 PostgreSQL 上的 Rust/Axum 小服务，有已发布的容器镜像。环境变量、Herald 登录门禁与完整 HTTP 接口见[自托管同步服务](./self-hosting)和 [OpenAPI 参考](./openapi)。
